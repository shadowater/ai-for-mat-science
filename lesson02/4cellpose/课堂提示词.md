# Cellpose 课堂提示词卡（学生用）

[返回教师手册](README.md) · [课堂讲义](课堂讲义.md) · [返回第二课入口](../README.md)

**怎么用**：在 VS Code 中打开 `lesson02/4cellpose`，再启动 Agent。一次只复制一张卡给 Agent。每张卡都要求它**运行并把真实输出贴出来**，不要只给代码。做完一张，核对“检查点”，再进入下一张。

**先做卡 0**。环境没装好，后面的卡都会失败。

**三条纪律**

1. 一次一步，不要让它一次生成整套流程。
2. 每步核对编号数、叠加轮廓和统计表；数字对不上就先停下。
3. 结果图要自己打开看，不要只看 Agent 的文字描述。

本目录下新建 `agent_demo/` 存放脚本和结果；不要修改 `素材/` 里的原图。

---

## 卡 0｜安装并配置 Cellpose（先做这张）

**目标**：用 uv 在当前文件夹建好环境、装好 Cellpose、下载模型。

**复制这段**：

```text
请帮我用 uv 在当前文件夹里配置 Cellpose 环境，按顺序做：
1. 先检查这台电脑有没有 uv；如果没有，先停下告诉我，不要换用别的方法；
2. 在当前文件夹创建 Python 环境，Python 用 3.13（电脑上没有就让 uv 自己下载）；
3. 安装这个文件夹里 requirements.txt 列出的依赖，Cellpose 必须是 4.2.1 版；
4. 提前下载 cpsam 模型，确认模型文件已经保存在电脑上；
5. 最后运行一次检查，告诉我：Python 在哪里、Cellpose 是什么版本、模型文件在哪里、有多大。
每一步都要真的执行，并把真实输出贴给我。哪一步失败就停下来说明原因，不要跳过。
```

**预期看到**

- 当前文件夹下出现 `.venv`；
- `Cellpose 4.2.1`；
- cpsam 模型保存在电脑上，大小约 1.23 GB（1,233,587,898 字节）；
- Agent 能成功加载一次模型。

**检查点**

- 版本不是 4.2.1，后面所有数量都没有可比性，先修环境。
- 模型名是不是 `cpsam`？4.2.1 的部分默认接口会下载 `cpsam_v2`，后面的数字会对不上。
- 模型没下载时，先按教师手册第 1.2 节准备好，不要在课堂上等 1 GB 下载。
- 如果它说“已经装好”，但没有贴出版本和模型大小，让它重新运行检查。

## 卡 1｜第一张图：TiO₂ 颗粒

**目标**：第一次运行分割，认识输入、输出和叠加图。

**复制这段**：

```text
请用 Cellpose 4.2.1 里的 cpsam 模型（模型名就叫 cpsam，
不要换成 cpsam_v2 或其他模型），把 素材/09_TiO2_SEM_1908248.tif 里的颗粒分割出来：
1. 只分析前 712 行；底部 56 行是仪器信息栏，不要分析；
2. 读图后先告诉我：分析区有多大、是灰度图还是彩色图；
3. 不要缩放或增强图片，其他设置用默认值；
4. 保存两张图到 agent_demo/（都用 PNG 格式）：一张每个颗粒不同颜色的标签图，
   一张原图加轮廓的叠加图；
5. 告诉我一共分割出多少个颗粒。
运行后把真实结果和图片路径贴给我。不要修改 素材/ 里的文件。
```

**预期看到**

- 分析区形状 `(712, 1024)`，是灰度图；
- 输出标签图与分析区同高同宽，背景为 0；
- Agent 报出 **214** 个实例；
- `agent_demo/` 下有两张图。

**检查点**

- 它加载的是不是 `cpsam`？Cellpose 4.2.1 的一些默认接口会用 `cpsam_v2`，数量会不同。
- 叠加图的轮廓和颗粒边缘对得上吗？
- 团聚处是把颗粒分开了，还是合成了一大块？
- 背景里有没有零星的彩色小块？

214 是本环境的参考值；差很多时先查模型、ROI 和缩放，再看叠图。

## 卡 2｜读懂标签图

**目标**：把整数标签和颗粒面积对应起来。

**复制这段**：

```text
先不要跑模型。scripts/fixtures/03_particles_reference_mask.tif 是一张已经做好的几何参考标签图
（测量练习用，不是样品图），请帮我读它：
1. 告诉我图的形状和数据类型；
2. 列出图里出现过的所有正整数编号，以及一共有几个编号；
3. 只看编号 1：数一数它占了多少个像素，并把这个编号的范围画成黑白图，
   保存到 agent_demo/label_1_mask.png；
4. 用一句话解释编号 0 和正整数分别代表什么。
运行后把真实结果贴给我。
```

**预期看到**

- 形状 `(256, 320)`，数据类型 `uint16`；
- 编号 `[1, 3, 7, 12, 16, 21, 25, 30, 42]`；
- 编号数量 **9**；
- 编号 1 的像素数 **1245**。

**检查点**

- 为什么 9 个颗粒的最大编号是 42？（编号只是身份，不表示数量。）
- 面积 1245 是怎么数出来的？（编号 1 覆盖的像素个数。）
- 背景 0 会不会被算成一个颗粒？

## 卡 3｜测量与边缘剔除

**目标**：从标签图得到面积、周长和“完整颗粒”表。

**复制这段**：

```text
请用几何参考图 scripts/fixtures/03_particles_reference_mask.tif 做测量（不是样品图）：
1. 对每个编号，算出它占多少像素（面积），并用 Crofton 方法（一种常用的
   周长估算方法）估算周长；算之前先把每个颗粒周围补一圈背景，四个方向都算；
2. 找出碰到图片最外一圈的编号，标记为“接触边缘”；
3. 输出一张表：编号、面积、周长、是否接触边缘；
4. 告诉我：一共有几个、剔除几个、保留几个、剔除的是哪些编号；
5. 把保留颗粒画成彩色叠加图，保存到 agent_demo/reference_kept.png；
   表格保存为 agent_demo/reference_particles.csv。
把表格和计数结果贴给我。
```

**预期看到**

- 全部 **9** 个；
- 剔除 **4** 个，编号 `[21, 25, 30, 42]`；
- 保留 **5** 个；
- 编号 1 面积 **1245 px²**，周长约 **125 px**。

**检查点**

- 剔除的是接触边缘的编号，不是面积最小的四个——为什么？
- 半径 20 像素的圆，连续几何面积约 1257 px²；测量值 1245，差在哪里？
- 剔除后统计的对象还能叫“全部颗粒”吗？

## 卡 4｜第二个视野：TiO₂ 电镜图

**目标**：在第二个视野上完成分割、计数和边缘剔除，并与主案例比较。

**复制这段**：

```text
请用和前面相同的 cpsam 模型，分割 素材/10_TiO2_SEM_1908250.tif：
1. 只分析前 712 行；底部 56 行是仪器信息栏，不要分析；
2. 图片不要缩放；目标判定阈值用 0（越低越容易把区域算成目标），
   最小颗粒用 15 像素（小于这个大小的对象会被丢掉），其他设置用默认值；
3. 告诉我：分析区有多大、一共分出多少个颗粒、有多少个碰到分析区四边、
   最后保留多少个；
4. 保存三张图到 agent_demo/（都用 PNG 格式）：原图、彩色标签图、
   原图加轮廓（绿色是保留，红色是接触边缘）。
运行后把真实结果和图片路径贴给我。
```

**预期看到**

- 分析区形状 `(712, 1024)`；
- 实例总数 **69**，接触边缘 **2**，保留 **67**；
- CPU 上约 1–2 分钟；
- `agent_demo/` 下有三张图。

**检查点**

- 如果数量和 69 差很多，先确认：是不是用 `cpsam`、有没有缩放图片、分析区是不是 712 行。
- 叠加图里，背景有没有零星的彩色小块？
- 稀疏视野里，小颗粒有没有被漏掉？
- 和 09 的 214、211 相比，这两个视野能直接合并统计吗？报告里应该怎样说明？

## 卡 5｜像素标定与面积分布（120 分钟版）

**目标**：把像素测量换算成物理单位，并看分布。

**复制这段**：

```text
继续用 09 的保留颗粒结果（如果前面没保存，就先按前面的方法补算）。
图片信息栏写着：视野宽度 7.520 微米，横向 1024 像素。
1. 算出每个像素代表多少微米；
2. 把保留颗粒的面积换算成平方微米，周长换算成微米；
3. 告诉我保留颗粒面积的中位数、最小值和最大值；
4. 画一张面积分布直方图，保存到 agent_demo/area_hist.png；
5. 说明这个换算依赖哪些假设。
把计算式和统计结果贴给我。
```

**预期看到**

- 每个像素约 `0.00734 微米`；
- 面积乘“每像素微米数的平方”，周长乘“每像素微米数”；
- 直方图保存在 `agent_demo/`。

**检查点**

- 为什么面积要乘两次像素尺寸，周长只乘一次？
- 图像被缩放、拼接，或像素不是正方形时，这个换算还成立吗？
- 中位数和平均值，哪一个更适合描述粒径分布？

## 卡 6｜参数对照（120 分钟版）

**目标**：只改一个设置，学会用叠图判断结果。

**复制这段**：

```text
在 09 上做三组对照（图像和 ROI 与第一张卡相同），其他设置不变：
A. 默认设置；
B. 最小颗粒改成 60 像素；
C. 目标判定阈值改成 0.3。
每组告诉我颗粒总数和保留数，并各保存一张轮廓叠加图到 agent_demo/。
用一张表比较三组，结合叠加图指出：哪一组背景误检更少，哪一组漏掉了小颗粒。
不要为了凑数量反复调参。
```

**预期看到**

- 三组数量不同，方向取决于图像；
- 背景误检通常随“最小颗粒”和“目标判定阈值”增大而减少；
- 小颗粒可能被过滤掉。

**检查点**

- 数量变少，是去掉了误检，还是漏掉了真颗粒？看叠图。
- 数量变多，是找回了小颗粒，还是把一个大颗粒切成了几块？
- 这三组用的是同一张图吗？如果是，结论应该怎样表述？

## 卡 7｜检查 Agent：让它交代依据

**目标**：区分“它记得”和“它验证过”。

**复制这段**：

```text
不要写新代码。根据刚才运行得到的真实结果回答：
1. 标签图里的 0 和正整数分别代表什么？
2. 这次用的模型是什么？目标判定阈值和最小颗粒大小各控制什么？
   在哪个文件里改的？
3. 参考图里编号 1 的面积是多少？面积怎么算出来的？周长为什么是估计值？
4. 参考图里哪几个编号被剔除，为什么？剔除后统计的是哪些颗粒？
5. 调参用的图和报告数字的图是不是同一张？如果是，结论应该怎样表述？
6. 哪些地方你不确定？请明确标出，不要编。
```

**检查点**

- 它说的形状、编号、面积，和你看到的终端输出一致吗？
- 它有没有把“目标判定阈值”和“最小颗粒大小”的作用说反？
- 它标为“不确定”的地方，你能不能自己复算？

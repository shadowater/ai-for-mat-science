## 1. 开场：这张图里有多少个颗粒（3 分钟）

**投屏原图**：`素材/09_TiO2_SEM_1908248.tif`。

**照读**：

> 这是一张 TiO₂ 颗粒的扫描电镜图。如果我要报“这批颗粒的中位粒径是多少”，第一步不是量，而是先决定：图里哪些像素属于同一个颗粒。今天我们就用 Agent 把这件事走完：从一张图，到一张颗粒表，再到一个可以写进论文的粒径分布。

**追问全班**：

> 人眼数不准，也不可重复。我们需要一个明确的规则：先让模型把每个颗粒标成一个编号，再按编号测量。这个“编号图”就是今天的主角。

## 2. 分割到底在做什么（7 分钟）

### 2.1 从分类到分割

**板书**（左侧）：

```text
图像分类：一张图 → 一个标签（猫 / 狗）
语义分割：每个像素 → 一个类别（颗粒 / 背景）
实例分割：每个像素 → 一个对象编号（颗粒 1、颗粒 2、……）
```

**照读**：

> 分类只回答“图里有什么”；语义分割回答“每个像素是什么”；实例分割还要回答“这个像素属于哪一个颗粒”。材料专业关心粒径分布，必须知道“哪一个”，所以我们需要实例分割。

### 2.2 模型输出的是编号图

**投屏** `素材/figures/fig_label_map.png`。

**照读**：

> Cellpose 输出的不是彩色图，而是一张和原图同样大小的整数矩阵。0 是背景，正整数是颗粒编号。编号 1、2、3 只是身份，不代表大小，也不代表顺序。彩色图只是把这个矩阵染上颜色，方便我们看。

**提问**：

- 如果一张图里有 9 个颗粒，最大编号可能是多少？为什么？
- 编号 7 的颗粒一定比编号 3 的大吗？

**要落到的结论**：

> 数量看“出现了多少个不同的正整数”，不看最大值。

### 2.3 语义分割不够用的例子

**投屏** `素材/figures/fig_semantic_instance.png`。

**照读**：

> 语义分割能把“颗粒”和“背景”分开，但两个粘在一起的颗粒会变成一整块。实例分割会把它们尽量分成两个编号。分得对不对，要看叠加轮廓，不能只看数量。

## 3. 从编号到面积、周长和“完整颗粒”（10 分钟）

### 3.1 面积就是数像素

**板书**：

```text
一个颗粒的面积 = 它占的像素个数
像素边长 s（μm）→ 物理面积 = 像素数 × s²
```

**照读**：

> 数字图像没有连续的边界，只有格子。一个颗粒覆盖 1245 个像素，它的像素面积就是 1245 px²。要知道多少平方微米，再乘一次像素边长的平方。

**提问**：为什么面积乘 `s²`，周长只乘 `s`？

**要落到**：面积是二维的，长和宽各缩放一次；周长是一维的，只缩放一次。

### 3.2 周长为什么是“估计值”

**照读**：

> 像素边界是锯齿状的。把锯齿边长直接相加，会随像素化方式跳动。Crofton 方法从四个方向统计边界穿过格子的次数，得到一个更稳定的估计。它仍然是估计值，所以报告时写“约”。

**给一个可核对的数**：

```text
半径 20 像素的圆：连续几何面积 π×20² ≈ 1257 px²，周长 2π×20 ≈ 125.7 px
课程参考图实测：面积 1245 px²，周长约 124.6 px
```

**照读**：

> 差不到 1%。这点差来自像素化和周长估计，不是模型错了。知道“理论上应该是多少”，是判断测量代码对不对的最快办法。

### 3.3 为什么要剔除接触边缘的颗粒

**投屏** `素材/figures/fig_edge_removal.png`。

**照读**：

> 一个颗粒如果压在图像边界上，我们只看到了它的一部分。它的面积一定偏小，放进粒径分布会把分布往小的一侧拉。处理办法不是“猜它有多大”，而是明确剔除，并在报告里写清楚：统计对象是“完整颗粒”。

**提问**：

- 剔除的是面积最小的四个吗？（不是，是碰到边界的四个。）
- 剔除之后，还能说“图里所有颗粒”吗？（不能，要说“完整颗粒”。）

**板书**（右侧）：

```text
全部 9 个 → 接触边缘 4 个 → 保留 5 个
编号只是身份：最大编号 42，数量仍是 9
```

**这一节由教师投屏演示，学生先看不做**，避免全班同时下载 1.2 GB 权重。

### 4.1 演示动作

在 `lesson02/4cellpose` 中启动 Agent，把[卡 0](课堂提示词.md#卡-0安装并配置-cellpose先做这张)整段发给它。教师边等边讲：

### 4.2 讲给学生听的重点

**照读**：

> 为什么反复强调版本？因为模型、依赖和参数任何一个变了，颗粒数就可能变。今天所有同学报出的 214，只有在 Cellpose 4.2.1、cpsam、同样的分析区域下才有可比性。换一个版本，数字不同不是谁算错了，而是实验条件变了。

> 为什么强调 `cpsam` 而不是 `cpsam_v2`？Cellpose 4.2.1 的部分默认接口会自动选 `cpsam_v2`。名字只差一点，权重不同，结果就不同。提示词里把模型名写死，是为了让全班在同一条件下比较。

### 4.3 检查点

- 版本是不是 **4.2.1**；
- 模型文件是不是 **`cpsam`**；
- 大小是否约 **1.23 GB**（1,233,587,898 字节）；
- Agent 是否真的加载了一次模型，而不是只说“已安装”。

**常见故障**：

| 现象 | 处理 |
| --- | --- |
| 说没有 `uv` | 先装 `uv`，不要临时改用 pip 或 conda |
| 下载很慢 | 课前把权重拷到 `C:\Users\<用户>\.cellpose\models\cpsam` |
| 版本不是 4.2.1 | 停下修环境，否则后面数字没有可比性 |
| 终端中文乱码 | 用 UTF-8 终端；`run_examples.py` 已自动切换 |

## 5. 学生实操一：第一次分割（卡 1，15 分钟）

### 5.1 发提示词

让学生把[卡 1](课堂提示词.md#卡-1第一张图tio₂-颗粒)发给 Agent。关键约束只有三条：

```text
用 cpsam（不要 cpsam_v2）
只分析前 712 行（底部 56 行是仪器信息栏）
不要缩放、不要增强，其他用默认值
```

### 5.2 等结果时讲什么

**照读**：

> 为什么只取前 712 行？原图 768 行，最下面 56 行是仪器的信息栏，不是样品。把它喂给模型，模型可能把文字和色块当成颗粒。分析区域必须是样品区域，这是数据预处理的一部分，不是模型能替我们判断的。

> 为什么不缩放？像素尺寸和颗粒大小是绑定的。缩放会改变每个颗粒占的像素数，面积、周长全部跟着变。今天先在原始像素上做，标定放到后面。

### 5.3 预期结果

- 分析区形状 `(712, 1024)`，灰度图；
- 模型报出 **214** 个实例；
- `agent_demo/` 下有彩色标签图和轮廓叠加图。

### 5.4 检查叠加图（重点，不要跳过）

让学生打开叠加图，按顺序看三件事：

1. **轮廓贴不贴边**：绿色/彩色线是不是沿着颗粒边缘走？
2. **粘连处**：两个粘在一起的颗粒，是被分开，还是合成一块？
3. **背景**：空白区域有没有零星的彩色小块？

**照读**：

> 数量只是入口，叠图才是证据。214 这个数可能是“214 个真颗粒”，也可能是“200 个真颗粒 + 14 个背景误检”。这两种情况数量一样，结论完全不同。

**提问**：

- 如果背景有一片彩色小块，应该先调哪个参数？
- 如果两个颗粒被合成一个，数量会偏大还是偏小？

**要落到**：背景误检优先看 `min_size` 和 `cellprob_threshold`；粘连合并会让数量偏小。

### 5.5 教师巡视清单

- 有没有人忘了 ROI，直接跑 768 行；
- 有没有人用了 `cpsam_v2`；
- 有没有人把图缩小后再跑；
- 叠加图有没有真的打开看。

## 6. 读懂标签、做测量（卡 2 + 卡 3，15 分钟）

这一节先用**几何参考图**，不跑模型。目的是把“编号、面积、边缘”讲清楚，避免模型误差干扰概念。

### 6.1 卡 2：读标签

**发[卡 2](课堂提示词.md#卡-2读懂标签图)**。预期：

- 形状 `(256, 320)`，数据类型 `uint16`；
- 编号 `[1, 3, 7, 12, 16, 21, 25, 30, 42]`；
- 编号数量 **9**；
- 编号 1 的像素数 **1245**。

**追问**：

> 为什么 9 个颗粒，最大编号是 42？

**照读**：

> 编号是身份标签，不是计数器。中间可能删过对象、合并过区域，编号就会跳。数颗粒要数“有多少个不同的正整数”，不是看最大值。

> 背景 0 会不会被算成一个颗粒？不会，代码只统计大于 0 的编号。但如果代码写错，把 0 也数进去，就会多出一个“颗粒”。这就是为什么要让学生自己核对编号列表。

### 6.2 卡 3：测量与边缘剔除

**发[卡 3](课堂提示词.md#卡-3测量与边缘剔除)**。预期：

- 全部 **9** 个；
- 接触边缘 **4** 个：`[21, 25, 30, 42]`；
- 保留 **5** 个；
- 编号 1：面积 **1245 px²**，周长约 **124.6 px**。

**板书核对**：

```text
9 个编号 → 4 个碰边 → 5 个完整
面积 1245 ≈ π×20² = 1257（差 0.9%）
周长 124.6 ≈ 2π×20 = 125.7（差 0.9%）
```

**提问**：

- 剔除的为什么不是面积最小的四个？
- 如果把碰边颗粒“补全”再统计，需要哪些额外假设？这些假设可靠吗？

**照读**：

> 剔除不是“删掉不好看的数据”，而是明确测量对象：我们只统计完整颗粒。报告里必须写清楚这一点，否则读者会以为你统计了全部颗粒。

## 9. 总结与作业（5 分钟）

### 9.1 三个数字

```text
09：214 个实例 → 剔除 3 个 → 保留 211 个
参考图：9 个 → 剔除 4 个 → 保留 5 个
像素标定：7.520 μm ÷ 1024 px ≈ 0.00734 μm/px
```

### 9.2 三个坑

1. **把模型输出当成真实颗粒数**：背景误检、粘连合并、漏检都会让数量偏。
2. **忘了 ROI 或缩放**：底部信息栏、缩放后的像素，都会让面积和数量失去可比性。
3. **只报数量不看叠图**：数量对不代表分割对。

### 9.3 三个习惯

1. 一次只让 Agent 做一步，要求它贴真实输出；
2. 每步核对编号数、叠加轮廓、统计表；
3. 用已知几何（圆、正方形、参考图）验证代码。

### 9.4 课后作业

1. 选 10 或 11，完整跑一遍，记录：实例数、剔除数、保留数。
2. 假设颗粒是圆形，用面积反推等效直径，给出中位数和四分位距。
3. 找一处分割错误（背景误检、粘连或漏检），截图并解释原因。
4. 用 200 字写一段“方法”描述，必须包含：模型与版本、分析区域、参数、边缘剔除规则、像素标定。

## 10. 120 分钟扩展一：像素标定与粒径分布（卡 5，15 分钟）

**发[卡 5](课堂提示词.md#卡-5像素标定与面积分布120-分钟版)**。

### 10.1 板书推导

```text
视野宽度 7.520 μm，横向 1024 px
s = 7.520 / 1024 ≈ 0.00734 μm/px
面积：A_μm² = N_px × s²
周长：P_μm = N_px × s
等效直径：d = 2√(A/π)
```

### 10.2 讲清楚假设

**照读**：

> 这个换算成立，需要几个条件：图像没有被缩放或拼接；像素是正方形的；标尺或视野宽度是准的；你分析的区域和标定用的是同一尺度。任何一个不成立，换算出来的微米数就不可信。

**提问**：

- 如果图像被缩小了一半，`s` 应该怎么变？
- 中位数和平均值，哪个更适合描述粒径分布？为什么？

**要落到**：分布常有长尾，平均值容易被少数大颗粒拉高；中位数更稳健，但两者都应该报告。

## 11. 120 分钟扩展二：参数对照（卡 6，15 分钟）

**发[卡 6](课堂提示词.md#卡-6参数对照120-分钟版)**。

三组：

```text
A. 默认
B. min_size = 60
C. cellprob_threshold = 0.3
```

### 11.1 讲参数的作用

| 参数 | 作用 | 调大后的典型后果 |
| --- | --- | --- |
| `min_size` | 丢弃小于该像素数的实例 | 背景碎点减少，小颗粒也被丢掉 |
| `cellprob_threshold` | 控制纳入目标区域的像素范围 | 目标区域收缩，弱边界可能漏检 |
| `diameter` | 典型颗粒直径 | 与目标尺寸不匹配时，可能过分割或欠分割 |

**照读**：

> 调参不是为了把数字调到某个“正确答案”。我们没有 Ground Truth，调参是在权衡两类错误：把背景算成颗粒，还是把真颗粒漏掉。判断依据只有一个：叠加图。

### 11.2 讨论

- 数量变少，是去掉了误检，还是漏掉了真颗粒？
- 数量变多，是找回了小颗粒，还是把一个大颗粒切成了几块？
- 三组用的是同一张图吗？结论应该怎样表述？

**要落到**：任何参数结论都必须绑定“哪张图、哪个区域、哪组参数”，不能写成普遍规律。

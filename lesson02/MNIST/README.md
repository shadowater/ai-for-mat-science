## 3. 每一步的详细指引

### Step 0｜开场：计算机看到的不是“7”，是 784 个数（5 分钟）

**【讲】**

> 先看这张图。人看到的是“7”，计算机看到的是一张 28×28 的表格，每个格子里是 0 到 255 的灰度值。把它拉直，就是 784 个数。今天这个任务，就是把这 784 个数变成 10 个分数，分数最高的那个就是预测的数字。
>
> 我们不手写代码。你们把要求说给 Agent，它写、它运行、它报结果；你们负责核对三样东西：形状、损失、准确率。

**【板书】**

```
图片 [28,28] → 拉直 [784] → 网络 → 10 个分数 → 取最大 → 预测数字
```

**【问】** “如果网络输出 10 个分数，第 3 个分数最高，预测是几？”（答：2，因为下标从 0 开始。）

---

### Step 1｜数据：一个 batch 是 64 张图（7 分钟）

**【学生操作】** 卡 1（见[课堂提示词](课堂提示词.md#卡-1环境与数据)）。

**【Agent 应输出】**

```text
训练集 60000 张，测试集 10000 张
images.shape = torch.Size([64, 1, 28, 28])  dtype = torch.float32
labels.shape = torch.Size([64])             dtype = torch.int64
像素范围 = -0.424 到 2.821
```

**【讲】**

> `[64, 1, 28, 28]` 四个数分别是：一次 64 张、1 个通道（灰度）、高 28、宽 28。标签 `[64]` 是 64 个 0–9 的整数。
>
> 像素原来是 0–255。`ToTensor()` 把它变成 0–1 的浮点数；再减均值 0.1307、除标准差 0.3081，就出现负数。标准化让输入尺度接近，训练更稳。这两个数是从训练集统计的，测试集不能参与。

**【检查点】**

- 为什么 batch 维度在最前面？（一次算多张，GPU/CPU 并行）
- 为什么标签是 `int64`？（分类任务的下标；CrossEntropyLoss 要整数标签）
- 60000 ÷ 64 ≈ 938，这就是一个 epoch 的 batch 数。

---

### Step 2｜看图：图像就是矩阵（6 分钟）

**【学生操作】** 卡 2。

**【讲】**

> 打开 `samples.png`。每张图上面的 `label` 是真实答案。你会发现有些字很潦草，人也要看一会儿——这为后面的错例分析埋个伏笔。
>
> 单张图是 `[1, 28, 28]`，加 batch 就是 `[64, 1, 28, 28]`。形状的第一个维度永远是 batch，不是图片内容。

**【检查点】**

- `ToTensor` 前：0–255 整数；后：0–1 浮点；标准化后：可正可负。
- 标签不需要 one-hot。CrossEntropyLoss 直接接受 0–9 的整数。

---

### Step 3｜搭网络：101,770 个参数在哪（12 分钟）

**【学生操作】** 卡 3。

**【Agent 应输出】**

```text
Sequential(
  (0): Flatten()
  (1): Linear(in_features=784, out_features=128, bias=True)
  (2): ReLU()
  (3): Linear(in_features=128, out_features=10, bias=True)
)
可训练参数：101,770
输入 [2,1,28,28] -> 输出 [2,10]
```

**【讲】**

> 这个网络只有三层计算：拉直、第一个全连接、第二个全连接，中间夹一个 ReLU。
>
> 参数在哪？第一层 784×128 个权重，加 128 个偏置，是 100,480；第二层 128×10 个权重，加 10 个偏置，是 1,290；合计 101,770。参数就是网络里“可以被数据改”的数。
>
> 输出 10 个数叫 logits，还不是概率。CrossEntropyLoss 内部会做 softmax，所以模型最后不要再加 softmax。

**【板书】**

```
[64,1,28,28] --Flatten--> [64,784]
--Linear 784→128--> [64,128] --ReLU--> [64,128]
--Linear 128→10--> [64,10] logits
参数：784×128+128 + 128×10+10 = 101,770
```

**【检查点】**

- 让学生自己按计算器算一遍 101,770。
- 为什么输出是 10，不是 1？（10 类分类，每类一个分数）
- ReLU 做了什么？（负数变 0，正数不变；引入非线性）

---

### Step 4｜训练一轮：loss 从 2.3 降到 0.3（10 分钟）

**【学生操作】** 卡 4。

**【Agent 应输出】** 类似：

```text
batch 0     loss 2.301
batch 100   loss 0.512
batch 200   loss 0.386
...
训练准确率 0.926
耗时 21.4 秒
```

**【讲】**

> 训练循环只有五行，顺序不能乱：
>
> ```python
> optimizer.zero_grad()   # 清掉上一批的梯度
> logits = model(images)  # 前向：建立计算图
> loss = criterion(logits, labels)  # 算损失：一个标量
> loss.backward()         # 反向：沿图算每个参数的梯度
> optimizer.step()        # 更新：按梯度改参数
> ```
>
> 一个 epoch 是把 60000 张图看一遍，约 938 个 batch。每个 batch 都做一次上面五步。
>
> 一开始 loss 约 2.3，因为 10 类随机猜，正确类的概率约 1/10，`-ln(0.1) ≈ 2.3`。训练后降到 0.3 左右，说明模型确实学到了东西。

**【检查点】**

- `zero_grad()` 不清会怎样？梯度会累加，更新方向错。
- `backward()` 之后梯度在哪？在每个参数的 `.grad` 里。
- 训练准确率 92.6% 是整轮的平均；训练早期批次还不会，所以偏低。

---

### Step 5｜测试：95.8% 意味着什么（10 分钟）

**【学生操作】** 卡 5。

**【Agent 应输出】** MLP 约：

```text
测试准确率 0.9576
混淆矩阵（行=真实，列=预测）
...
各类准确率：0:0.980 1:0.975 ... 3:0.928 ... 9:0.961
```

**【讲】**

> 测试集 10000 张，训练时一张都没用过。95.76% 表示 9576 张判对，424 张判错。
>
> 看混淆矩阵的对角线：对角线是判对的数。非对角线告诉你错在哪。比如真实 3 被判成 8 有 20 张，真实 4 被判成 9 有 25 张。这两个数字在手写时本来就容易混。
>
> 打开 `misclassified.png`。有些图人也认不出——这不是模型“笨”，是数据本身模糊。模型错误和人觉得难，往往是相关的。

**【检查点】**

- 训练准确率 92.6%，测试 95.8%，为什么测试反而高？（训练准确率是整轮平均，包含早期批次；测试是训练完统一算。）
- 对角线之和除以 10000 等于准确率，让学生随机挑一行核对。
- 测试集只能看一次。反复根据测试结果调参，测试集就“泄漏”了。

---

### Step 6｜换 CNN：参数更少，反而更准（15 分钟）

**【学生操作】** 卡 6。

**【Agent 应输出】**

```text
CNN 可训练参数：20,490
1 轮测试准确率 0.9809
```

**【讲】**

> MLP 把图拉直，丢掉了“上下左右”的位置关系；每个像素对每个隐藏单元都有一个独立权重，参数多，但不认识局部笔画。
>
> CNN 用 3×3 的卷积核在图上滑动，同一个核在所有位置共享权重。它先学局部边缘、笔画，再组合成数字。池化把 28×28 降到 14×14、再降到 7×7，保留主要响应，减少计算。
>
> 结果：CNN 只有 20,490 个参数，比 MLP 少五倍，准确率却从 95.8% 升到 98.1%。**参数多不等于好，结构是否适合数据更重要。**

**【板书】**

```
[64,1,28,28] --Conv16--> [64,16,28,28] --Pool--> [64,16,14,14]
--Conv32--> [64,32,14,14] --Pool--> [64,32,7,7]
--Flatten--> [64,1568] --Linear--> [64,10]
参数：160 + 4,640 + 15,690 = 20,490
```

**【检查点】**

- 卷积核 3×3，为什么输出还是 28×28？（padding=1）
- 池化 2×2 后为什么是 14×14？
- 20,490 怎么算？Conv1 16×1×3×3+16=160；Conv2 32×16×3×3+32=4,640；FC 1568×10+10=15,690。

### Step 7｜只改一个设置：控制变量（13 分钟）

**【学生操作】** 卡 7。

**【预期结果】**

| 设置 | 参数量 | 测试准确率 |
| --- | ---: | ---: |
| MLP hidden=128，1 轮 | 101,770 | 约 95.8% |
| MLP hidden=32，1 轮 | 25,450 | 约 94.0% |
| CNN，3 轮 | 20,490 | 约 98.7% |

**【讲】**

> 这三组只有一处不同，其他都一样：同样的数据、同样的种子、同样的测试集。这才叫对照。
>
> 第一组到第二组：隐藏单元从 128 降到 32，参数少了，准确率降了约 1.8 个百分点。容量不够，学不全。
>
> 第二组到第三组：换结构、多训练两轮，参数更少，准确率反而更高。说明结构比单纯堆参数重要。
>
> 但注意：我们拿同一个测试集比较了三组。严格说，测试集已经被用来“选模型”了。科研里应该留一个验证集做选择，测试集只在最后用一次。

**【检查点】**

- 参数越多一定越好吗？
- 训练 3 轮比 1 轮好多少？如果训练 20 轮呢？（可能过拟合，测试不再升。）
- 为什么不能一直看测试集调参？

### Step 8｜把“图”讲清楚（10 分钟）

**【学生操作】** 卡 8。

**【讲】**

> 现在回到今天的核心：**图**。这里说的图，是网络结构图和计算图，不是图神经网络。
>
> 前向时，数据从输入流到输出，每一层是一个节点，张量是边。PyTorch 会自动把这条路径记下来，这就是计算图。`loss.backward()` 从 loss 出发，沿图反方向走，用链式法则算出每个参数的偏导。`optimizer.step()` 再用这些偏导改参数。
>
> 所以深度学习的关键不是手推梯度，而是：**你定义前向，框架自动反向。** 前提是每一步都可微。

**【板书/投影】**

```
前向（建图）：
x[64,1,28,28]
  Flatten        → [64,784]
  Linear(W1,b1)  → [64,128]
  ReLU           → [64,128]
  Linear(W2,b2)  → [64,10]  logits
  CrossEntropy(y)→ loss（标量）

反向（沿图反走）：
loss.backward()
  → ∂loss/∂W2, ∂loss/∂b2
  → ∂loss/∂W1, ∂loss/∂b1
optimizer.step()
  → 更新 W1,b1,W2,b2
```

**【检查点】**

- 哪些是参数，哪些是临时激活？参数跨 batch 保留，激活算完就丢。
- 为什么评估用 `torch.no_grad()`？（不建图，省内存、更快。）
- `zero_grad()` 为什么必要？（PyTorch 默认累加梯度。）

## 4. “图的组成”详解

这一节是给学生补概念用的，教师可以按需投屏。

### 4.1 网络结构图：层是节点，张量是边

MLP：

| 节点 | 类型 | 形状 | 是否可训练 |
| --- | --- | --- | --- |
| 输入 x | 数据 | [64, 1, 28, 28] | 否 |
| Flatten | 操作 | [64, 784] | 否 |
| W1 | 参数 | [784, 128] | 是 |
| b1 | 参数 | [128] | 是 |
| Linear 1 | 操作 | [64, 128] | 否 |
| ReLU | 操作 | [64, 128] | 否 |
| W2 | 参数 | [128, 10] | 是 |
| b2 | 参数 | [10] | 是 |
| Linear 2 | 操作 | [64, 10] | 否 |
| logits | 激活 | [64, 10] | 否 |
| loss | 标量 | [] | 否 |

参数计算：

```
W1: 784 × 128 = 100,352
b1: 128
W2: 128 × 10 = 1,280
b2: 10
合计: 100,352 + 128 + 1,280 + 10 = 101,770
```

CNN：

```
[64,1,28,28]
  Conv2d(1→16, 3×3, padding=1)  → [64,16,28,28]
  ReLU                          → [64,16,28,28]
  MaxPool2d(2)                  → [64,16,14,14]
  Conv2d(16→32, 3×3, padding=1) → [64,32,14,14]
  ReLU                          → [64,32,14,14]
  MaxPool2d(2)                  → [64,32,7,7]
  Flatten                       → [64,1568]
  Linear(1568→10)               → [64,10]
```

参数计算：

```
Conv1: 16×1×3×3 + 16 = 160
Conv2: 32×16×3×3 + 32 = 4,640
FC:    1568×10 + 10 = 15,690
合计:  20,490
```

### 4.2 计算图：前向建图，反向求导

- **节点**：一次运算（矩阵乘、加法、ReLU、交叉熵）。
- **边**：张量从哪个节点流到哪个节点。
- **前向**：按拓扑顺序算，得到 loss。
- **反向**：从 loss 开始，按反拓扑顺序，用链式法则算每个参数的偏导。
- **特点**：图是每个 batch 临时建的；`backward()` 后释放；参数和梯度跨 batch 保留。

一个有用的类比：前向是“把原料加工成成品”，反向是“从成品的误差倒推每道工序该负多少责任”。`optimizer.step()` 就是按责任大小调整每道工序的参数。

### 4.3 参数 vs 超参数

| 类别 | 例子 | 谁决定 |
| --- | --- | --- |
| 参数 | W1、b1、W2、b2 | 训练数据 + 优化器 |
| 超参数 | 隐藏单元数、学习率、batch 大小、训练轮数、网络结构 | 人 |
| 数据 | 60000 训练、10000 测试 | 人划分 |

这张表就是 1.4 讲的“**人定框架，数据定参数，独立数据定好坏**”。

### 4.4 为什么“图”让深度学习可行

- 只要每个节点可微，整张图就可微。
- 框架记录前向操作，反向自动套链式法则。
- 你换层、加层、改结构，不用重新手推梯度。
- 这就是为什么我们能快速试 CNN、ResNet、Transformer：前向怎么写，反向就怎么自动算。

## 5. 本机实测结果

环境：Windows，CPU，torch 2.13.0+cpu，Python 3.14，4 线程，seed=42。

| 模型 | 参数量 | 训练 1 轮 | 训练 3 轮 | 单轮耗时 |
| --- | ---: | ---: | ---: | ---: |
| MLP 784→128→10 | 101,770 | 测试 95.76% | — | 21 秒 |
| MLP 784→32→10 | 25,450 | 测试 94.03% | — | 20 秒 |
| CNN 16/32 | 20,490 | 测试 98.09% | 测试 98.73% | 33–39 秒 |

说明：

- 准确率会因机器、线程数、随机种子略有波动，±0.5% 正常。
- 训练准确率（如 92.64%）低于测试准确率（95.76%）是正常的：前者是整轮平均，包含早期批次；后者是训练完统一评估。
- 这些数字对应参考脚本 `mnist_reference.py`。学生生成的代码若细节不同（例如是否标准化、优化器不同），数字会在合理范围内变化；重要的是趋势和数量级。

## 6. 常见问题

**Q1：`No module named 'torch'`**

VS Code 选错解释器。运行 `python check_env.py`，看 `解释器` 一行；在 VS Code 右下角切换到同一个 Python。再安装：

```bash
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
```

**Q2：MNIST 下载卡住**

提前把教师机的 `data/MNIST/raw/` 四个 `.gz` 文件拷给学生。或者在网络好的地方下载后整体拷贝 `data/`。`download=True` 发现文件存在就不会再下载。

**Q3：终端中文乱码**

用 VS Code 自带终端；或在 PowerShell 先执行 `chcp 65001`。这不影响训练结果，只影响显示。

**Q4：训练很慢**

CPU 一轮 20–40 秒是正常的。检查是否误用了 `num_workers>0`（Windows 上可能卡住），改为 0；关闭其他占 CPU 的程序；不要一上来跑 20 轮。

**Q5：准确率只有 10% 左右**

按顺序查：

1. 损失是不是 `CrossEntropyLoss`，模型输出是不是 raw logits（没有再套 softmax）；
2. 标签是不是 0–9 的整数；
3. 优化器是不是在模型定义之后创建，参数有没有传进去；
4. 每个 batch 有没有 `zero_grad()`；
5. 训练集和测试集有没有弄反。

**Q6：Agent 说“准确率 99%”，但没运行**

要求它贴出终端输出、`history.json` 和文件修改时间。没有运行记录的指标，一律不算。

**Q7：Agent 一次改了很多文件**

让它停下来，列出改了哪些文件、每个文件改了什么；必要时用 git 或备份恢复。课堂上坚持“一张卡、一个文件、一次运行”。

**Q8：CNN 比 MLP 慢，值得吗**

一轮多 10–15 秒，但准确率高 2 个多百分点，参数还少。课堂上先跑 1 轮看趋势，有时间再跑 3 轮。

**Q9：测试集能不能反复用**

不能。反复根据测试集调参，测试集就参与了模型选择。课堂上为了省时间可以比较几组，但要明确告诉学生：科研中应留验证集，测试集只用一次。

**Q10：没有 GPU 可以吗**

可以。MNIST 很小，CPU 足够。这门课不要求 GPU。

**Q11：Agent 请求确认命令时怎么办**

只批准 `python`、`pip` 和对 `mnist_demo/` 的读写；不要批准删除其他目录、修改 `.claude` 配置或联网上传文件。课堂上让学生看清命令再点允许。

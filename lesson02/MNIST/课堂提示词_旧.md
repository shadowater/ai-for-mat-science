# MNIST 课堂提示词卡（学生用）

[返回教师手册](README.md) · [返回第二课入口](../README.md)

**怎么用**：在 VS Code 中打开 `lesson02/MNIST`，再启动 Claude Code。下面的路径都以这个文件夹为当前目录。一次只复制一张卡给 Agent。每张卡都要求它**运行并把真实输出贴出来**，不要只给代码。做完一张，核对“检查点”，再进入下一张。

**三条纪律**

1. 一次一步，不要让它一次生成整个项目。
2. 每步核对 shape、参数量、准确率；数字对不上就先停下。
3. 测试集只用于最后评价，不能拿来反复调参。

## 卡 1｜环境与数据

**目标**：确认 PyTorch 能跑，MNIST 能读进来，认识一个 batch 的形状。

**复制这段**：

```text
我们在课程文件夹里做一个 MNIST 手写数字识别项目。先只做环境检查和数据准备。
请在 mnist_demo/ 下创建 data.py：
1. 用 torchvision.datasets.MNIST 下载数据到 mnist_demo/data；
2. 定义 get_loaders(batch_size=64)，返回 train_loader 和 test_loader；
3. 变换用 ToTensor() 和 Normalize((0.1307,), (0.3081,))；
4. 在 __main__ 里打印：训练集和测试集数量、一个 batch 的 images.shape 和 dtype、
   labels.shape 和 dtype、像素最小值和最大值。
运行 python data.py，把真实输出完整贴给我。不要只给代码，也不要创建其他文件。
```

**预期看到**

- 训练集 60000 张，测试集 10000 张
- `images.shape = [64, 1, 28, 28]`，`labels.shape = [64]`
- 像素范围约 `-0.424` 到 `2.821`（标准化后）

**检查点**

- 四个数字分别是什么：batch 大小、通道数、高、宽？
- 为什么标签是 `int64`，而不是浮点数？

## 卡 2｜先看图，再看数字

**目标**：把“图像”还原成“数字矩阵”，理解输入到底是什么。

**复制这段**：

```text
在 mnist_demo/ 下创建 show_samples.py：从训练集取前 8 张图，画成 2×4，
每张图标题写真实标签，保存为 mnist_demo/samples.png。
运行后告诉我保存路径，并回答：
1. 单张图的张量形状是什么？
2. ToTensor 之前和之后，像素值范围分别是多少？
3. 标准化之后，像素值为什么会出现负数？
```

**预期看到**：`samples.png`；单张图 `[1, 28, 28]`；原始 0–255 整数，ToTensor 后 0–1 浮点，标准化后出现负数。

**检查点**

- 28×28 = 784 个数字，就是模型的 784 个输入。
- 标签是 0–9 的整数，不是 one-hot。

## 卡 3｜搭一个最小网络

**目标**：看懂网络由哪些层组成，算清参数量。

**复制这段**：

```text
在 mnist_demo/ 下创建 model.py，只定义 MLP：
Flatten -> Linear(784,128) -> ReLU -> Linear(128,10)。
在 __main__ 里打印模型结构、可训练参数总数，
并用 torch.randn(2,1,28,28) 验证输出 shape。
运行 python model.py，把输出贴给我。
```

**预期看到**

- 参数量 **101,770**
- 输入 `[2,1,28,28]`，输出 `[2,10]`

**检查点**

- 101,770 = 784×128 + 128 + 128×10 + 10，你能对上每一项吗？
- 输出的 10 个数是什么？（10 个类别的分数，叫 logits，还不是概率）

## 卡 4｜定义损失，训练一轮

**目标**：走一遍 `zero_grad → forward → loss → backward → step`。

**复制这段**：

```text
在 mnist_demo/ 下创建 train.py：
1. 从 data.py 导入 get_loaders，从 model.py 导入 MLP；
2. 损失用 CrossEntropyLoss，优化器用 Adam(lr=0.001)；
3. batch_size=64，训练 1 个 epoch；
4. 每个 batch 依次执行 optimizer.zero_grad()、前向、loss、loss.backward()、optimizer.step()；
5. 每 100 个 batch 打印一次平均 loss，整轮结束打印训练准确率；
6. 固定随机种子 42，保存模型到 mnist_demo/outputs/model.pt。
运行 python train.py，贴出真实输出和总耗时。
```

**预期看到**：loss 从约 2.3 降到 0.3 左右；训练准确率约 92%–93%；CPU 上约 20–40 秒。

**检查点**

- 一个 epoch 有多少个 batch？（60000 ÷ 64 ≈ 938）
- 为什么每轮开始要 `zero_grad()`？不清会怎样？
- `loss.backward()` 之后，梯度存在哪里？

## 卡 5｜测试、混淆矩阵与错例

**目标**：区分训练表现和测试表现，学会看错在哪里。

**复制这段**：

```text
在 mnist_demo/ 下创建 evaluate.py：加载 outputs/model.pt，在测试集上：
1. 打印总准确率；
2. 打印 10×10 混淆矩阵（行=真实，列=预测）；
3. 打印每个数字的准确率；
4. 找出 12 个预测错误的样本，保存为 mnist_demo/misclassified.png，
   标题写 true 和 pred。
运行并贴出准确率、混淆矩阵和图片路径。
```

**预期看到**：MLP 测试准确率约 95%–96%；错例多集中在 3/5/8、4/9、7/9 这些形近字。

**检查点**

- 训练准确率 92%，测试准确率 96%，这正常吗？为什么？
- 混淆矩阵的对角线是什么？哪两个数字最容易混？
- 错例图里，有些是不是人也难认？

## 卡 6｜用 CNN 再跑一次

**目标**：同样任务，换一种网络结构，比较参数量和准确率。

**复制这段**：

```text
在 model.py 里增加一个 CNN，不要改动 MLP：
Conv2d(1,16,3,padding=1) -> ReLU -> MaxPool2d(2)
-> Conv2d(16,32,3,padding=1) -> ReLU -> MaxPool2d(2)
-> Flatten -> Linear(32*7*7,10)。
给 train.py 增加 --model {mlp,cnn} 参数。
运行 python train.py --model cnn --epochs 1，
贴出参数量、测试准确率和耗时，并与 MLP 比较。
```

**预期看到**：CNN 参数量 **20,490**，测试准确率约 98%，仍比 MLP 参数少。

**检查点**

- CNN 参数更少，为什么反而更准？
- 卷积核在图像上滑动，和全连接“每个像素一个权重”有什么不同？
- 池化把 28×28 变成 14×14、再变成 7×7，丢掉了什么，保留了什么？

## 卡 7｜只改一个设置，做对照

**目标**：理解超参数的影响，学会控制变量。

**复制这段**：

```text
保持数据划分、随机种子和测试集不变，做三组对照，用一张表报告：
A. MLP hidden=128，1 epoch
B. MLP hidden=32，1 epoch
C. CNN，3 epochs
每组报告：参数量、测试准确率、每轮耗时。
不要用测试集调参，只比较这一次。
```

**预期看到**（参考值，允许小幅波动）

| 设置 | 参数量 | 测试准确率 |
| --- | ---: | ---: |
| MLP hidden=128，1 轮 | 101,770 | 约 95.8% |
| MLP hidden=32，1 轮 | 25,450 | 约 94.0% |
| CNN，3 轮 | 20,490 | 约 98.7% |

**检查点**

- 参数越多一定越好吗？
- 训练 3 轮比 1 轮好多少？再多训练会一直变好吗？
- 这三组都用同一个测试集比较，有什么风险？

## 卡 8｜把“图”讲清楚，并检查 Agent

**目标**：用自己的话解释计算图，并让 Agent 交代它的工作。

**复制这段**：

```text
不要写新代码。请用刚才的真实张量形状解释一次训练的计算图：
1. 输入到 logits，每一层的张量形状；
2. 哪些张量是参数，哪些是临时激活；
3. loss.backward() 做了什么，optimizer.step() 做了什么，zero_grad() 为什么必要；
4. 评估时为什么用 torch.no_grad()。
如果哪一步你不确定，明确说出来，不要编。
```

**再复制这段**：

```text
请检查 train.py 有没有数据泄漏：测试集是否参与训练或调参？
标准化参数从哪里来？给出文件名和行号作为依据。
```

**检查点**

- 它说的形状，和你运行输出一致吗？
- 它有没有把“参数”和“超参数”混为一谈？
- 它标为“不确定”的地方，你能不能自己复算？

# 课程基础与科研需求问卷

这份问卷用于了解学生起点、选择正式课案例和安排环境支持。当前为在本仓库维护、可复制到问卷平台的问卷草稿；尚未创建在线表单或发送给学生。

- [中文问卷](questionnaire.zh.md)
- [English questionnaire](questionnaire.en.md)

两版均有 17 道题，题号、题型、选项、示例和要求对应。修订期间保留原题号，便于逐题审阅；原 Q2、Q5、Q7、Q8、Q9 已删除。英文先起草和核对，再翻译中文。实际发布时可按学生需要选择语言，不要求同一人填写两遍。

## 一、问卷想回答的教学问题

| 教学问题 | 对应题目 | 对课程的用途 |
|---|---|---|
| 有多少学生需要文件操作方面的支持 | Q6 | 决定预习补充材料、第一课回顾和助教支持 |
| 电脑和软件安装是否会阻碍参与 | Q4、Q22 | 比较本地 Docker 与服务器方案，安排安装帮助 |
| 编程与相关工具的接触程度 | Q10、Q20 | 安排 Python 选学的难度和支持方式 |
| 图片、结构化数据及 AI 概念是否熟悉 | Q11–Q13 | 确定基础概念需要讲到什么深度 |
| 学生研究哪些体系、常用哪些测试 | Q3、Q14–Q16 | 选主案例、样例数据格式和工具 |
| 最希望 AI 帮忙解决哪些任务 | Q17–Q19 | 排定六次实践和学生需求专题 |
| 更需要哪类教学支持 | Q21 | 决定短视频、图文、答疑和练习投入 |

不以“电脑盲”作为学生标签。文件操作、代码经验、AI 经验和专业经验分别分析；常用 AI 聊天工具也不代表能配置环境或处理文件。

## 二、平台录入建议

1. 问卷首页使用学生版说明，保留“无编程基础也可以参加”“不计成绩”“不需要提交数据”等表述。
2. Q1 填写姓名，Q22 选填；其他题按学生版保留适用的“不确定”“暂未确定”“尚未接触”等选项。不要新增学号、电话等非必要字段。若平台记录身份，不要把整份问卷标为匿名。
3. Q6、Q10、Q11 为矩阵单选题。手机上若显示拥挤，可拆成逐行单选，保持题目含义和选项不变。
4. Q13、Q14、Q15、Q16 为多选。Q13“以上都没有用过”及“不确定属于哪一类”与具体工具分类互斥；Q15“暂时没有科研数据”、Q16“尚未处理过数据或制作过图表”与具体条目互斥。Q14“尚未接触测试或图像数据”与具体测试项互斥；“主要做文献、理论或模拟计算”可以和其他项目并选。
5. Q17 最多选三项并排序；“目前还不确定”与具体需求互斥。若平台不支持“限选三项并排序”，改成限选三项多选，再加一题“其中最希望先解决哪项”，只展示前题所选内容。导出时保留与原 Q17 的对应关系。
6. Q21 最多选两项；“没有特别偏好”与其他选项互斥。
7. Q12 选“从未使用过”时，可以跳过 Q13，并在导出中区分逻辑跳过与未回答。Q14 没做过实验不能直接跳过科研需求题：学生仍可能有文献或模拟任务。
8. 先请 2–3 位不同基础的人试填，重点检查手机矩阵显示、选项歧义和填写时长。当前以约 10–12 分钟为设计目标，未经试填验证，不作为学生速度要求。

## 三、如何汇总基础情况

对 Q6 的每一行，分别统计 A、B、C、D 的人数和比例。分母采用该行的有效作答人数，并注明缺答人数。A 表示缺少接触或不清楚，不能直接写成“完全不会”；B 表示需要说明或帮助。

可以回答用户最关心的“基础薄弱者有多少”，但先把口径说清：

- **文件操作指导需求**：统计“找到下载文件、解压、在指定位置保存文件”三项中至少一项选 A/B 的人数。计数时按人去重。这是课程支持口径，不是能力认证。
- **较集中的文件操作指导需求**：另列上述三项中至少两项选 A/B 的人数，帮助估计分组答疑规模。
- **设备与环境支持**：Q4 统计主要使用 Windows 电脑、Mac 和 Linux 服务器的人数；Q22 汇总主动提及的安装或设备困难。Q22 为选填，未提及困难不代表没有支持需求。
- **Python 起点**：按 Q10 的 Python 行分布报告，再与 Q20 选学意愿对照；没有编程经验不等于缺少文件操作能力。
- **AI 概念起点**：分别报告 Q11 各行分布；Q12 的使用频率不作为理解程度的替代。

正式第一课可结合实际操作，进一步了解同学需要哪些帮助。可以在教学安排中使用“需分步指导”“可独立操作”“可参与同伴互助”等描述。同伴互助需再征求本人意愿，Q6 选 D 不等于承诺担任助教。

## 四、如何据此选择课程案例

- Q14 统计每种测试的实际接触人数，Q15 统计可提供的数据形式，Q16 观察现有工具。多选题比例之和超过 100% 是正常的，报告时写明分母。
- Q17 分开报告“第一优先需求”和“进入前三的需求”，不把所有选择视为同等优先级。
- 将 Q18 按图像、曲线、文献、写作、批量处理、模拟及其他任务归类，同时保留原文。检查是否有明确输入、希望得到的输出和人工检查方式。
- 将兴趣、实际问题和可获得的样例一起考虑。例如很多人想学曲线处理，但样例主要是红外，就优先用红外作完整主例，其他测试展示迁移。
- Q19 仅表示愿意进一步讨论，不能据此把学生资料直接公开或上传服务。只有愿意提供且实际可用的样例，才能计入“可用案例”数量。
- 暂无课题或数据的学生使用课程示例，仍可完整参加实践。不要要求他们为填写问卷先完成科研方案。

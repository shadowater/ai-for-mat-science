# 第一次正式课：计算机基础、AI 与 Agent（120 分钟）

[返回课程入口](README.md) · [既有内容总纲](01_第一次课教学大纲.md)

教师审阅稿。本稿是整节课的执行大纲：前半段诊断并回顾预习内容，后半段解释 AI 与 Agent，再完成一次小任务。现有讲义作为备课与课后查阅材料，不要求课堂逐页讲完。

## 一、对象与学习目标

面向材料、化学、化工研究生。假定学过高等数学和线性代数，已接触预习材料；不假定会编程，也不将完成预习等同于已经掌握。

本课结束时，学生应能：

1. 区分计算与存储、内存与硬盘，解释文件、程序和运行环境的基本关系。
2. 区分路径、文件格式、文本编码；看懂简单 JSON，并理解命令需要相应程序执行。
3. 在建模案例中指出人选择的内容与数据学习的内容，区分训练、使用和检验。
4. 说明语言模型生成内容、Harness 协调工具、工具实际执行之间的分工。
5. 用可用的 Agent 完成一次读取、计算和保存任务，核对实际输出。

全课主线：**计算机如何执行程序 → 文件如何表达信息 → 模型如何学习和生成 → Harness 如何连接操作 → 如何验证结果。**

## 二、课前准备与课堂边界

- 学生尽量提前装好计划使用的桌面端，或确认网页 Agent 可用。课上只确认入口与处理少量问题；安装未完成者先使用可用的备用入口或与同伴共同观察，不停下全班等待安装。
- 教师提前启动本地小模型，检查最小二乘网页、Notebook 与 Harness；准备已有运行记录和输出文件，以便故障时展示并明确说明是先前结果。
- 将课程样例放在学生容易找到的文件夹中，使用现有[课堂实践材料](内容/05_课堂实践与结果检查.md)，不临时要求学生准备自己的科研数据。
- 演示只使用一个命令行环境，不并排讲 Windows、macOS、Linux 命令清单。学生任务用自然语言描述，不要求手写 Python。
- 第 4 章的教师演示和后续实践采用“读取数据—计算—保存—核验”的共同结构。若工具入口不同，说明具体实现的差别，不要求学生部署教师的最小 Harness。

## 三、时间总表

| 时间 | 环节 | 主要方式 | 本段产出或检查 |
| --- | --- | --- | --- |
| 0—10 分钟 | Agent 入口确认与开场 | 快速提问、一次短对话 | 每人或每组有可用入口，记录一个待解释的问题 |
| 10—30 分钟 | 计算机、命令与运行环境 | 诊断回顾、单一命令和 Notebook 演示 | 能区分计算与存储，说明谁执行命令 |
| 30—45 分钟 | 文件、编码与信息格式 | 打开同一样例，观察与修改 | 能区分路径、编码、格式，看懂工具请求字段 |
| 45—90 分钟 | 第 4 章：从建模到语言模型与 Harness | 数学桥接、短动画、真实执行 | 能解释学习与执行的分工 |
| 90—110 分钟 | 学生实践与结果核验 | 独立或结对操作 | 一份实际输出与一次核对记录 |
| 110—120 分钟 | 理解检查、答疑与机动 | 三问检查、反馈科研需求 | 明确本课结论与尚未解决的问题 |

合计 120 分钟。各段时间包含互动；遇到共性困难使用最后的机动时间，优先按文末方案压缩选讲内容。

## 四、逐段教学安排

### 0—10 分钟：先有一个可用助手，再提出问题

**必要内容：**确认 Agent 入口可用，能发起一次短对话。不展开产品比较、模型排行榜或完整 API 配置教程。

让学生询问一个预习中不清楚的概念，例如“内存和硬盘有什么区别”。请一位同学说出：答案是否清楚？怎样确认它说得对？

留下两个问题，暂不完整回答：

> 它为什么能回答？如果让它读取电脑上的文件，又是谁在读取？

**衔接：**先看它所运行的计算机，以及操作真正发生所需要的条件。

**材料：**[Agent 上手与模型服务](内容/01_Agent上手与模型服务.md)。

### 10—30 分钟：计算机怎样执行我们的要求？

#### 10—17 分钟：硬件分工与操作系统

先问：“内存不足”和“存储空间不足”是同一个问题吗？根据回答补充：

- CPU 执行通用计算；GPU 适合许多可并行的运算，后面再连接矩阵计算。
- 内存保存正在使用的数据，硬盘用于持久保存；显存为 GPU 提供工作数据空间。
- 操作系统管理资源、文件和运行中的程序。应用软件依靠这些条件工作。

展示一台电脑的设备信息即可。速度、容量与持久性的差异用于解释分工，不展开硬件型号与采购。

#### 17—24 分钟：图形界面、命令与 Python

只演示一次创建文件夹或改名的命令，说明文本命令是另一种表达操作的方式，需要由相应程序解析与执行。

在已有 Notebook 中修改半径并运行计算或绘图。说明 Python 代码由解释器及底层库等支持，最终由硬件执行；不画成所有代码都必经汇编的单一路线。

**检查：**屏幕上出现一段代码，等于它已经运行了吗？答案：不等于，要看是否交给相应执行程序，以及实际运行结果。

#### 24—30 分钟：路径与运行环境

- 相对路径依赖当前工作目录；绝对路径明确文件所在位置。
- 环境变量提供程序运行时可读取的设置；PATH 是其中用于查找程序的目录列表。
- 用 `code .` 解释“找到程序”与“传入当前目录”是两件事，不要求现场配置所有电脑。

**衔接：**程序找到文件之后，还必须按正确规则解释其中的数据。

**材料：**[计算机与运行环境](内容/02_计算机与运行环境.md)、[演示入口](演示/README.md)。

### 30—45 分钟：文件中的信息怎样被解释？

#### 30—35 分钟：文件、后缀与编码

用两道预习检查切入：

1. 把文件名改为 `.csv`，它就一定成为合法 CSV 吗？
2. 同一文本出现乱码，是文字一定丢失了吗？

解释后缀是标识，实际内容必须符合相应格式；文本编码规定字节怎样对应字符。错误解码可能造成乱码，不能把编码和格式混为一谈。编码切换只做简短展示，乱码梗留作备课例子。

#### 35—41 分钟：CSV 与 JSON

复用现有样例，找到同一个样品字段：

- CSV 用行列表示表格，适合许多实验数据。
- JSON 用字段和值组织信息，值也可以包含列表或其他对象。

不背语法规则；请学生在 JSON 中指出一个字段名及其值。提醒：合法 JSON 只是数据，不会自动执行操作。

#### 41—45 分钟：Markdown 与公式

打开一份 Markdown，观察正文、标题和公式预览。只修改一个参数或一处公式，说明源文本与显示结果的关系。

**衔接：**前面讲的是信息怎样保存和解释；接下来讲模型怎样把信息用于预测与生成。文本编码不等于模型的嵌入向量。

**材料：**[文件与科研信息](内容/03_文件与科研信息.md)。XML、Office 内部结构、完整 LaTeX 语法、PDF/OCR 与比例尺本次不展开。

### 45—90 分钟：第 4 章——从熟悉的科研建模到 AI Agent

这一段负责解释开场使用的工具。复用[完整讨论稿](内容/04_AI与Agent的工作方式/新版教学大纲_讨论稿.md)与[50 分钟备课大纲](内容/04_AI与Agent的工作方式/50分钟必要内容大纲.md)，按下列 45 分钟安排取舍，不将两份大纲叠加讲授。

#### 45—49 分钟：AI 与人工规则

- AI 是研究推理、学习、感知等智能任务的学科方向；具体系统同样通过程序实现，不意味着具有意识。
- 专家系统由人提供知识与规则，程序据此推理。简举价态约束排除不合理结构，不展开历史与图形题。
- “输入到输出的映射”是本课采用的数学视角，不是 AI 与普通程序的独有分界。

#### 49—55 分钟：熟悉的模型与函数族

用 Arrhenius 方程唤起参数拟合经验，指出输入、输出、已选关系与待拟合参数。

$$k(T)=A\exp\left(-\frac{E_a}{RT}\right),\qquad \hat y=f_\theta(x).$$

人选择候选函数族，数据帮助确定具体函数。传统机器学习和神经网络都有这一共同点；科学模型还可能以方程及求解条件表达，不全部等于专家系统。

**提问：**拟合活化能时，我们选择的是方程形式，还是已经选定方程中的参数？

#### 55—63 分钟：从最小二乘理解学习

以溶解度预测定义任务，再明确切换到三个虚构标定点展示直线拟合；不把演示点称作真实溶解度数据。

$$\hat y=ax+b,\qquad L=\sum_i(y_i-\hat y_i)^2.$$

手动改变一次参数，再播放梯度下降。解释残差、损失、训练与使用；直接解作为备课参考，不必再次操作。

梯度由偏导数组成，梯度下降沿负梯度方向更新参数。训练后必须用未参与训练的数据检验，关注外推范围。

**检查：**换训练数据后，参数可能改变，模型形式是否一定改变？

#### 63—71 分钟：输入描述与神经网络

回到 ESOL：由分子描述符建立多元线性回归，不逐项计算系数。

用两层网络说明矩阵、偏置与非线性变换：

$$\hat y=W_2\sigma(W_1x+b_1)+b_2.$$

重点区分：关系表达能力不足，与输入缺失信息不是同一问题。深度学习可把中间表示的形成纳入学习，仍需人选择输入、结构和目标。反向传播只用一句“链式法则计算梯度”说明。

**检查：**若温度影响结果但没有记录，换大网络能保证解决吗？不能。

#### 71—79 分钟：语言模型怎样生成文本？

接回前面的文件编码，逐步说明：

> 字符 → token（模型处理的文本片段）→ 编号 → 嵌入向量 → 结合上下文计算 → 下一个 token 的概率分布 → 选择并继续生成。

嵌入表是训练参数；中间向量不等于最终概率分布。只展示一次实际切分与短续写，不讲向量算术、模型尺寸和完整训练过程。

上下文是本次调用提供的信息，普通对话不等于更新权重。生成内容仍需核验。

#### 79—90 分钟：Harness 与真实执行

重新提出开场问题：“如果它能读文件，谁在读取？”

- Harness 是围绕模型组织上下文、协调工具与收集结果的程序层。
- 接回路径：文件名存在于对话中，不等于工具已经找到并读取文件。
- 接回 JSON：请求用字段和值表达工具名称和参数。
- 接回命令与 Python：模型生成请求，工具及运行环境实际执行。

只运行一次读取半径、计算面积、保存报告的成功流程。在调用处暂停，指出请求、工具结果与实际文件。教师最小 Harness 是受引导流程，不是通用自主规划能力的证明。

**向实践交接：**下一段大家改变输入或任务要求，独立检查输出，不重复讲解整套原理。

**材料：**[第 4 章入口](内容/04_AI与Agent的工作方式/README.md)、[最小二乘](演示/最小二乘/README.md)、[本地语言模型](演示/本地语言模型/README.md)、[最小 Harness](演示/最小Harness/README.md)。

### 90—110 分钟：学生完成一次任务并核验

采用[既有课堂任务与检查要求](内容/05_课堂实践与结果检查.md)。统一沿用读取、处理、保存、检查四步，不同时开放多个科研项目。

- **90—93 分钟：**确认输入文件、目标输出和保存位置。学生在任务中明确这些条件。
- **93—103 分钟：**使用可用 Agent 完成任务；遇到错误时查看实际反馈、补充必要信息。教师重点处理共性问题。
- **103—108 分钟：**打开输出，核对至少一个原始字段或计算值；涉及计算时借助前面 Notebook 或计算器独立检查。
- **108—110 分钟：**请一组展示“实际输出在哪里、检查了什么、发现了什么问题”。

最低完成证据是一份可打开的输出与一句核验说明，不以对话中的“已完成”作为唯一证据。工具暂不可用的学生与同伴共同检查，仍参与结果判断。

### 110—120 分钟：理解检查、答疑与机动

先用约 3 分钟检查：

1. 神经网络哪些由人选择，哪些通过数据学习？
2. 训练误差小，是否能证明新分子预测可靠？
3. Agent 说文件已经保存，怎样确认？

其余时间回答课堂共性问题，并记录学生希望后续解决的科研任务。未解决的安装问题单独记录，不在结束阶段重新展开全套配置。

## 五、前后概念如何衔接

| 前半段基础 | 第 4 章中的用途 |
| --- | --- |
| CPU、GPU | 理解模型计算的硬件基础，不把 GPU 当作智能来源 |
| 编码、字符 | 与 token 和嵌入区分，理解不同表示层次 |
| JSON | 看懂工具名称与参数，不把数据格式当作执行机制 |
| 命令、解释器、环境 | 理解模型输出如何交给实际程序执行 |
| 路径、工作目录 | 理解文件访问需要具体位置和可用工具 |
| Markdown、保存文件 | 理解报告是实际产物，需要打开和核验 |

## 六、内容取舍与故障备用

**不进入本次必讲内容：**硬件采购与装机、多系统命令清单、Python 语法课、完整公式语法、K-Means/SVM/PCA、Uni-Mol 架构、反向传播推导、词向量类比、RAG、长期记忆和多 Agent。保留在原讲义中供查阅。

**发生超时时，按顺序压缩：**设备信息展示、Markdown 现场修改、梯度下降公式解释、神经网络公式展开、现场续写。保留实际执行演示、学生核验和最后三问。

**发生演示故障时：**展示既有实测请求、结果和报告，明确是先前运行记录。仍区分模型生成与工具执行；不以备用讲解无限延长课时。

本稿用于安排课堂，正文和操作说明继续维护在对应讲义中。后续试讲重点记录各段实际耗时与学生卡点，再决定需要补讲哪些基础。

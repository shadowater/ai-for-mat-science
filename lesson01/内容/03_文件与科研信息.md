# 文件与科研信息

文件保存数据，软件根据编码和文件格式解释数据。

## 一、字节、编码与文件格式

文件在数字层面保存为一串字节；一个**字节（byte）**由 8 个位组成，每个位可表示 0 或 1。软件按照规则解释这些数据，才能显示文字、图像或表格。

| 层次 | 作用 | 例 |
| --- | --- | --- |
| 文本编码 | 规定字符与字节的转换方式 | UTF-8、GBK、Big5 |
| 文件格式 | 规定数据结构与字段含义 | CSV 的行列、JSON 的名称和值、图片的尺寸与像素数据 |
| 文件后缀 | 提供格式线索 | `.csv`、`.json`、`.png` |
| 读取软件 | 按编码和格式规则呈现内容 | 文本编辑器显示 CSV 原文，表格软件将它排成单元格 |

后缀为用户和软件提供格式线索，文件内容仍由内部字节和组织规则决定。把 `.csv` 改名为 `.png` 后，文件内容仍是 CSV 文本；生成图片需要按图片格式写入像素等数据。程序可能依据后缀、文件头、内容结构或用户设置选择解析方式，有些格式还需要用户指定读取方法。

在文件浏览器中显示后缀，再用 VS Code 打开[第一课课堂样例](../课堂样例/README.md)，对照文件名与内容。

## 二、编码与乱码：同一串字节，可能被读成不同的字

**Unicode** 为字符定义编号；**UTF-8** 把这些编号编码为字节。GBK 常见于旧中文资料，**Big5（大五码）**常见于早期繁体中文资料。

保存和读取使用不同编码时，屏幕上可能出现乱码。早期网站或仪器导出文件需要按其实际编码读取。参考[《你缺失的那门计算机课》字符与编码章节](https://www.criwits.top/missing/characters-and-encodings.html)。

- **“锟斤拷”**：一种形成过程是两个替代字符 `�` 按 UTF-8 保存，再按 GBK 读取。原字符一旦被替代字符覆盖并保存，恢复原文就需要寻找原始文件或备份。
- **“烫烫烫”**：重复的十六进制 `CC` 字节按 GBK 每两个一组解码会显示成“烫”。调试时的内存填充被当作文字输出，也可能产生类似现象；排查时需要同时检查编码和数据来源。

打开课堂样例中 [`sample.zh.txt`](../课堂样例/sample.zh.txt) 的副本，在 VS Code 状态栏选择编码，分别用 GBK 和 UTF-8 重新打开。重新打开会按所选编码解释现有字节；保存会按所选编码写入字节。

## 三、用同一个样品认识 CSV、JSON 和 XML

以下三种格式都记录样品 `M-02`，字段和组织方式各有不同。

### CSV：用文本保存表格

```csv
sample_id,file_name
M-02,figure.svg
```

CSV 通常用逗号分隔各列、换行区分各行。第一行是列名，第二行是样品记录。Excel 工作簿还可保存多个工作表、单元格样式和图表。字段内含逗号时，CSV 使用引号包住字段。

打开[CSV 样例](../课堂样例/sample.csv)和[同名 Excel 文件](../课堂样例/sample.xlsx)，对照文本中的列名、数据行和表格中的单元格。CSV 格式详见 [Data Carpentry 的说明](https://datacarpentry.github.io/spreadsheet-ecology-lesson/05-exporting-data.html)。

### JSON：名称与值，也可以包含列表

```json
{
  "sample_id": "M-02",
  "figure": "figure.svg",
  "measurements": [1.2, 1.4, 1.3],
  "fictional": true
}
```

花括号 `{}` 包住这里的一组信息；**key（键）**是名称，**value（值）**是对应内容，用冒号连接。值可以是文字、数字、真假值，也可以是列表或另一组信息。这里的列表用**方括号 `[]`**表示。

打开[JSON 样例](../课堂样例/sample.json)，对照上面代码中的 `measurements` 列表。列表中的数值是用于展示结构的虚构数据。JSON 结构详见 [MDN《使用 JSON》](https://developer.mozilla.org/zh-CN/docs/Learn_web_development/Core/Scripting/JSON)。

### XML：用成对标签组织层次

```xml
<sample>
  <sample_id>M-02</sample_id>
  <figure>figure.svg</figure>
</sample>
```

`<sample>` 是开始标签，`</sample>` 是结束标签，里面还可以嵌套其他标签。XML 用标签表达层次，具体应用规定标签的名称和含义。[XML 样例](../课堂样例/sample.xml)中的 `M-02` 和 `figure.svg` 与 CSV、JSON 中的内容对应。格式转换会改变数据的组织方式和标记。详见 [W3C XML 标准](https://www.w3.org/TR/xml/)。

## 四、Office 文档的格式与软件

这些文档保存文字、数值、样式、布局、图片、公式和对象关系，需要支持相应格式的软件解析。**文件格式和加密是两项独立的设置。** 常见的 `.docx`、`.pptx`、`.xlsx` 使用 Office Open XML 标准，通常由 XML 和图片等内容打包而成；微软 Office、WPS 等兼容软件都能读取。各软件支持的排版和功能范围有所差异，使用 WPS 打开 Word、PPT、Excel 文件时也可检查版式与功能。早期 `.doc`、`.ppt`、`.xls` 使用另一组格式，需要按各自的格式规则解析。参考 [ECMA-376 Office Open XML 标准](https://ecma-international.org/publications-and-standards/standards/ecma-376/)。

文档加密由软件单独设置。文本编辑器会显示复杂格式的原始字节，阅读文档时应使用支持该格式的软件。

CSV、JSON 便于检查和编程处理数据。Office 格式可保存复杂排版、公式和工作簿结构。导出 CSV 时，工作表样式和公式等内容可能发生变化。

## 五、Markdown：把文字组织成可阅读的笔记

Markdown 用文本标记表示标题、列表和链接。常用写法如下：

| 写法 | 用途 |
| --- | --- |
| `# 样品记录` | 一级标题 |
| `## 处理方法` | 二级标题 |
| `- 原始数据` | 列表项 |
| `**需要核对**` | 加粗 |
| `[文献](https://doi.org/...)` | 链接，实际使用时填完整 DOI |
| `![样品示意](figure.svg)` | 引用本地图片，路径相对当前笔记 |
| 反引号包住短文字 | 行内代码，例如文件名或命令 |
| 三个反引号包住多行内容 | 代码块，保留代码或报错的排版 |

代码块展示代码。Python 解释器执行代码后才会产生运行结果。

### 在 Markdown 中写公式

支持数学渲染的阅读工具可以显示 LaTeX 风格公式。用 `$...$` 写行内公式，用单独成行的 `$$...$$` 写独占一行的公式。示例：

```markdown
半径为 $r$ 的圆，其面积为 $A=\pi r^2$。

$$
\sigma = \frac{F}{A_0}
$$
```

| 写法 | 含义 |
| --- | --- |
| `r^2`、`A_0` | 平方、下标 |
| `\frac{F}{A_0}` | 分数 |
| `\sqrt{x}` | 平方根 |
| `\alpha`、`\beta`、`\gamma` | α、β、γ |
| `\theta`、`\lambda`、`\mu` | θ、λ、μ |
| `\pi`、`\sigma`、`\Delta` | π、σ、Δ |

复制[示例笔记](../课堂样例/note.zh.md)并保持它与配图的相对位置。修改标题，把 `$A=\pi r^2$` 改成 `$d=2r$`，加入一个希腊字母，然后保存并打开预览。更多写法见[公式速查](../课堂样例/公式速查.md)。

## 六、文献与图像：回顾已有基础

PDF 可能包含文字，也可能由扫描图像组成；OCR 把图像中的字识别为文字。[文字层 PDF](../课堂样例/text-example.pdf)中的文字可以直接选中；从[图像层 PDF](../课堂样例/image-only-example.pdf)提取文字通常需要 OCR。[文献记录](../课堂样例/paper-record.zh.md)中的 DOI、题名、作者和年份用于核对来源。

图像中的像素是一小格颜色，坐标说明位置，比例尺联系图上距离与实际距离。打开[本课比例尺练习图](../课堂样例/比例尺练习.svg)：100 像素对应 10 μm，30 像素就对应 3 μm。位图以像素表达图像，矢量图以形状等描述图像；[样品示意图](../课堂样例/figure.svg)用于观察 SVG 格式。真实测量时应依据测量图上的标定信息计算。

图像识别、测量和文献解析将在后续实践课展开。

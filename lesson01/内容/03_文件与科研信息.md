前面看到，程序可以通过文本命令操作文件。现在继续问：**文件保存的到底是什么，软件又怎样知道应该如何读取？**

## 一、同样是 0 和 1，为什么能变成文字、图像和表格？

文件在数字层面保存为一串字节；一个**字节（byte）**由 8 个位组成，每个位可表示 0 或 1。软件按照规则解释这些数据，才能显示文字、图像或表格。

| 层次 | 解决什么问题 | 例 |
| --- | --- | --- |
| 文本编码 | 怎样把字符存为字节，再把字节读回字符？ | UTF-8、GBK、Big5 |
| 文件格式 | 数据按什么结构组织，字段怎样解释？ | CSV 的行列、JSON 的名称和值、图片的尺寸与像素数据 |
| 文件后缀 | 给用户和软件什么格式线索？ | `.csv`、`.json`、`.png` |
| 读取软件 | 是否支持并正确使用这些规则？ | 文本编辑器显示 CSV 原文，表格软件将它排成单元格 |

后缀是方便识别的标记，不决定文件真实内容。把 `.csv` 改名为 `.png` 不会得到图片；程序可能依据后缀、文件头、内容结构或用户设置选择解析方式。也不能保证每个文件都能靠内容自动、唯一地识别。

先让文件浏览器显示后缀，再用 VS Code 打开[预习课二样例](../../预习课/预习课二/README.zh.md)，对照文件名和实际内容。

## 二、编码与乱码：同一串字节，可能被读成不同的字

**Unicode**为字符定义统一的编号；**UTF-8**是一种把这些编号保存为字节的编码方式。GBK 是旧中文资料中常见的编码，**Big5（大五码）**则常见于早期繁体中文资料。这里了解用途即可，不背编码表。

如果保存和读取时使用了不匹配的编码，就可能出现乱码。例如，有些早期网站或仪器导出文件，需要按其实际编码读取。直接复用[《你缺失的那门计算机课》字符与编码章节](https://www.criwits.top/missing/characters-and-encodings.html)及预习课二的演示。

- **“锟斤拷”**：一种形成过程是两个替代字符 `�` 按 UTF-8 保存，再按 GBK 读取。如果原字符已经被替换后保存，切换编码未必能恢复原文。
- **“烫烫烫”**：重复的十六进制 `CC` 字节按 GBK 每两个一组解码会显示成“烫”。调试时的内存填充被当作文字输出，也可能产生类似现象；不能把所有乱码都解释为“文件选错编码”。

**课堂演示：**打开 `sample.zh.txt` 的副本，在 VS Code 状态栏选择编码，用 GBK 重新打开，再用 UTF-8 重新打开恢复显示。只改变读取方式，显示乱码时不编辑或保存。重新打开与按另一编码保存的区别，见[预习课二的编码说明](../../预习课/预习课二/README.zh.md)。

## 三、用同一个样品认识 CSV、JSON 和 XML

复用已有样品 `M-02`，减少额外背景。学生要看懂结构、找到字段，暂不编写解析程序。

### CSV：用文本保存表格

```csv
sample_id,file_name
M-02,figure.svg
```

CSV 通常用逗号分隔各列、换行区分各行。第一行是本例的列名，第二行是一条样品记录。CSV 不保存 Excel 的多个工作表、单元格样式或图表。字段内也可能包含逗号，此时需按规则使用引号；本次只看简单样例。

打开[现有 CSV 样例](../../预习课/预习课二/materials/sample.csv)，指出样品编号和文件名。详细讲解继续使用本地 [Data Carpentry CSV 选段](../../预习课/预习课二/materials/data-carpentry/csv.zh.md)。

### JSON：名称与值，也可以包含列表

```json
{
  "sample_id": "M-02",
  "figure": "figure.svg",
  "measurements": [1.2, 1.4, 1.3],
  "fictional": true
}
```

花括号 `{}` 包住这里的一组信息；**key（键）**是名称，**value（值）**是对应内容，用冒号连接。值可以是文字、数字、真假值，也可以是列表或另一组信息。这里的列表用**方括号 `[]`**表示，不是圆括号。

先查看[预习课二的 JSON 样例](../../预习课/预习课二/materials/sample.json)，再看上面新增的 `measurements` 列表。这里的三个数仅为结构示意，没有实际测量含义。可复用 [MDN《使用 JSON》](https://developer.mozilla.org/zh-CN/docs/Learn_web_development/Core/Scripting/JSON)中“什么是 JSON”和结构示例，无需完成 JavaScript 练习。

### XML：用成对标签组织层次

```xml
<sample>
  <sample_id>M-02</sample_id>
  <figure>figure.svg</figure>
</sample>
```

`<sample>` 是开始标签，`</sample>` 是结束标签，里面还可以嵌套其他标签。XML 使用这些标记表达层次；标签名称及其含义由具体应用约定。打开[本课 XML 样例](../演示/sample.xml)，找到 `M-02` 和 `figure.svg`，与 CSV、JSON 对照即可。教师参考 [W3C XML 标准](https://www.w3.org/TR/xml/)。

**提问：**三个文件能表达同一条样品信息，是否意味着它们只需改后缀就能互相转换？

## 四、Word、PPT 和 Excel 为什么需要相应软件？

这些文档不仅保存文字或数值，还可能保存样式、布局、图片、公式和对象关系，需要支持相应格式的软件解析。**格式复杂不等于加密。** 常见的 `.docx`、`.pptx`、`.xlsx` 使用 Office Open XML 标准，通常由 XML 和图片等内容打包而成；并非只有微软软件才能读取。不同软件对排版和功能的支持程度可能不同。早期 `.doc`、`.ppt`、`.xls` 则是另一组格式，不能直接套用上述打包方式。参考 [ECMA-376 Office Open XML 标准](https://ecma-international.org/publications-and-standards/standards/ecma-376/)。

给文档设置加密密码是另外一个操作。文本编辑器打不开或显示乱码，并不能说明文件已加密。

对于简单数据交换，CSV、JSON 容易直接检查和编程处理；对于复杂排版、公式和工作簿结构，Office 格式也有其用途。导出 CSV 前，要知道哪些格式和功能会丢失。

## 五、Markdown：把文字组织成可阅读的笔记

Markdown 是文本写法，工具把标记显示成标题、列表、链接等。先复用[本地 Markdown 速查](../../预习课/预习课二/materials/markdown-guide/markdown-cheat-sheet.zh.md)，只演示下列常用项：

| 写法 | 用途 |
| --- | --- |
| `# 样品记录` | 一级标题 |
| `## 处理方法` | 二级标题 |
| `- 原始数据` | 列表项 |
| `**需要核对**` | 加粗 |
| `[文献](https://doi.org/...)` | 链接，实际使用时填完整 DOI |
| `![样品示意](figure.svg)` | 引用本地图片，路径相对当前笔记 |
| 反引号包住短文字 | 行内代码，例如文件名或命令 |
| 三个反引号包住多行内容 | 代码块，保留代码或报错的排版 |

代码块只是在文档里显示内容，不会因为写上 `python` 就自动运行程序。这个区别会在下一部分的工具调用中再次出现。

### 在 Markdown 中写公式

支持数学渲染的阅读工具可以显示 LaTeX 风格公式。用 `$...$` 写行内公式，用单独成行的 `$$...$$` 写独占一行的公式。示例：

```markdown
半径为 $r$ 的圆，其面积为 $A=\pi r^2$。

$$
\sigma = \frac{F}{A_0}
$$
```

| 写法 | 含义 |
| --- | --- |
| `r^2`、`A_0` | 平方、下标 |
| `\frac{F}{A_0}` | 分数 |
| `\sqrt{x}` | 平方根 |
| `\alpha`、`\beta`、`\gamma` | α、β、γ |
| `\theta`、`\lambda`、`\mu` | θ、λ、μ |
| `\pi`、`\sigma`、`\Delta` | π、σ、Δ |

**课堂动作：**复制[现有示例笔记](../../预习课/预习课二/materials/note.zh.md)，保持它与配图的相对位置，修改标题，把 `$A=\pi r^2$` 改成 `$d=2r$`，再补一个希腊字母。保存并打开预览。更多写法查阅[预习课二公式速查](../../预习课/预习课二/materials/math-in-markdown.zh.md)，不要求背诵。

## 六、文献与图像：回顾已有基础

PDF 可能包含文字，也可能只有扫描图像；OCR 把图像中的字识别为文字。比较预习课二的两份 PDF，尝试选中文字，并说明为什么识别结果还要对照原页。DOI 标识文献，题名、作者和年份帮助核对来源；找到记录不等于取得全文。

图像中的像素是一小格颜色，坐标说明位置，比例尺联系图上距离与实际距离。例如 100 像素对应 10 μm，30 像素就对应 3 μm。位图以像素表达图像，矢量图以形状等描述图像。预习课二的 SVG 是示意图，不能拿它作经过标定的测量图。

上述内容以现有预习材料作回顾；具体识别、测量和文献解析安排在后续实践课。

# 上下文与常见模型：这一次，模型实际看到了什么？

[返回本章大纲](README.md) · [上一节：语言模型](05_从文本向量到语言模型.md) · [下一节：Agent Harness](07_文本命令与Agent_Harness.md)

建议用时：12—15 分钟。先对照续写与聊天，再用真实请求解释历史记录、文件与上下文。模型名称表只需认识入口，不要求记忆型号或排名。

## 一、为什么输入“姚明是”，回答又从“姚明是”开始？

上一节的本地演示中，用户输入了“姚明是”，聊天模型却重新组织了一句“姚明是一位……”。这可以用来区分两种输入方式。

**原文续写**：把这一段文本作为前缀，接着生成。

```text
姚明是▌
```

**聊天**：把用户消息放入对话格式，在助手的位置生成回复。

```text
〈用户开始〉
姚明是
〈用户结束〉
〈助手开始〉
▌
```

这里的中文标记只是示意，真实模型使用特定的控制 token 或格式。两者底层都在继续生成 token，但开始生成之前的序列不同；聊天模式是在回复用户，不一定直接补完用户那句话。

同一个聊天模型也可以接收原始续写输入，不过它经过聊天训练，脱离预期格式不保证表现更好。不要把“换了接口”误讲成“换了一套模型权重”。

**课堂动作：**在网页输入“姚明是”，再用上一节的 `inspect_llm.py next --text '姚明是'` 查看原始续写的下一个 token。网页可能输出整句，脚本只请求一个 token，不能直接拿二者的长度比较能力。

## 二、系统提示词与聊天模板不是一回事

**聊天模板**将“谁说了什么”的消息列表，转换成模型期望的文本序列。**系统提示词**是其中一种可能的消息内容，用于提供行为要求；它不是全部聊天格式。

常见角色包括：

| 角色 | 含义 |
| --- | --- |
| user | 用户提出的问题或提供的资料 |
| assistant | 之前的助手回答，以及接下来要生成回答的位置 |
| system | 系统提供的行为要求，是否存在取决于具体服务和配置 |
| tool | 工具实际执行后返回的信息，后续小节展开 |

角色格式由具体模型和服务决定，不要求把上表当成所有 API 的完整协议。

**本课当前已关闭系统提示词：**本地入口会删除请求中的 system 消息，但仍保留用户／助手的角色分隔。模型仍然具有训练得到的行为，关闭系统提示词不会把它变回未经聊天训练的基础模型。

本地演示没有让模型执行工具。不要把消息中写了一个文件名，或助手说“读取成功”，当成已经发生真实操作。

## 三、上下文是什么？可以类比本次作答的资料包

**上下文**是模型这次计算实际能够使用的信息。可以类比一次开卷练习：长期学习形成的能力是一回事，桌上这次拿到的题目和材料是另一回事。

在语言模型中，长期训练得到的规律主要体现在参数中；当前问题、提供的资料、选入的历史对话和工具结果，则可以成为本次输入的一部分。

这个类比用于区分信息来源，不意味着模型像人一样记忆或理解。

| 情况 | 是否自动成为这次可用信息？ |
| --- | --- |
| 文件保存在电脑某个目录 | 不会，仅仅存在还没有被读入 |
| 用户粘贴了一段记录 | 如果实际提交给模型，就进入输入 |
| 上次对话中说过一句话 | 取决于这次请求有没有带上相应历史或摘要 |
| 程序读取文件后提交正文 | 提交的正文可以成为上下文 |
| 工具执行了计算 | 还需要把执行结果交回模型，才能用于后续回答 |

因此，“模型应该知道”之前，先检查它实际收到什么，而不是只看我们在界面上见过什么。

## 四、历史对话通常怎样进入下一次请求？

聊天界面会给人“它记住了上一句”的感觉。常见实现是：外围程序保存对话，再把需要的历史连同新问题送给模型。

例如第二次提问时，可以提交：

```json
{
  "messages": [
    {"role": "user", "content": "样品编号是 Z-731。"},
    {"role": "assistant", "content": "收到记录。"},
    {"role": "user", "content": "样品编号是什么？请只回答编号。"}
  ]
}
```

如果只提交最后一条问题，前面的编号不在这次请求里，模型就缺少那条记录。

不同产品也可能通过服务端会话标识、摘要或检索材料提供历史，不一定每次由用户端重新发送完整列表。但无论采用哪种方式，相关信息都需要以某种方式进入这次计算。

缓存可以加速处理重复前缀，也不等于模型自动获得了另一次独立请求中没有提供的历史。

## 五、真实演示：同一个模型，改变提供的信息

运行[上下文对照脚本](../../演示/本地语言模型/context_demo.py)：

```bash
python3 context_demo.py
```

在脚本所在目录执行，使用已经启动的 WSL 本地服务。记录文件是课程自编的虚构[教学样品记录](../../演示/本地语言模型/教学样品记录.txt)，内容为“样品编号是 Z-731。”，不涉及真实学生或实验数据。

脚本依次提交五组独立请求，保持模型与生成设置一致，改变消息列表：

| 场景 | 这次提供什么 | 本机一次实际输出 |
| --- | --- | --- |
| 没有记录 | 只有编号问题 | `编号` |
| 带上历史记录 | 编号记录、示意的助手确认、当前问题 | `Z-731` |
| 丢掉历史只发末句 | 再次只提供问题 | `编号` |
| 只提供文件名 | 请读取某个文件，但没有文件正文或读取工具 | `编号：2023-04-01` |
| 实际读文件后提供正文 | 脚本读取文件，明确将内容放进用户消息 | `Z-731` |

这是 Qwen3-0.6B Q8_0 的一次真实运行，temperature=0.7、seed=42。见[完整请求、模板和实测输出](../../演示/本地语言模型/上下文实测.json)。不要把这组结果当作所有模型或所有重复运行必然出现的答案。

在第二种场景中，“收到记录。”是教师为构造历史而写好的示意消息，不是这轮脚本先调用模型生成的确认；最终答案则由真实模型生成。

### 教师怎样讲这个结果？

- **先看证据，再看答案。**第二、五种请求确实提供了编号；第一、三、四种没有提供记录。
- **文件名不是文件内容。**第四种即使编出日期样式编号，也没有读取成功的依据。
- **读取是程序做的。**第五种是 Python 先读取文本，再把正文发送给模型；没有由模型自主决定读取，不是 Agent 演示。
- **回答碰巧正确也不证明依据充分。**若模型猜中了某个编号，仍需检查它有没有获得相关记录。

### 保留一次失败，避免把演示讲成必然成功

第一次尝试使用了更长记录，并在问题中要求“不知道请写不知道”。这台小模型在五种情况下都回答不知道，包括已经提供记录的情况。该次[原始失败记录](../../演示/本地语言模型/上下文实测_初次失败.json)也保留在目录中。

随后简化记录与问题，才得到上表结果。两次输入不相同，不能将它们当成严格控制变量的能力比较，也不能只归因于其中某一个提示词。

我们由此只得出有限结论：**提供资料是作出有依据回答的必要环节之一，但模型可能仍不能正确利用。**需要实际检查，不能靠格式漂亮或提示词长短保证正确。

## 六、为什么不能无限增加上下文？

**上下文窗口**表示模型或服务一次能够处理的 token 范围，具体限制与模型、实现和配置有关。输入、历史、模板及输出通常共同占用相应预算，实际还要看服务如何管理。

本课 WSL 演示明确配置为 2,048 token 上下文、单并发。这个值是本次运行设置，不是 Qwen3-0.6B 模型卡所标最大能力的同义词，也不是只能输入 2,048 个汉字。

超过预算时，服务可能拒绝请求、截断内容、移动窗口或进行其他处理，不能默认总会保留最重要的部分。应用可能先做摘要或检索，再挑相关内容送入模型。

即使没有超过长度上限，信息太多、相互冲突或缺少清楚的对应关系，也可能使回答变差。更长的输入不自动等于更充分的有效依据。

**课堂动作：**查看对照报告中 `formatted_prompt_tokens`，比较单条问题与包含历史、文件正文的输入长度。这个计数来自模板化文本的实际分词，不是按字符数猜测；完整报告也保留了服务器返回的 usage，以便核对实现差异。

## 七、读文献时，怎样给出足够的信息？

假设希望模型汇总论文中的某个测试结果，可以先准备：

1. 明确任务：提取哪个样品、哪种测试和哪些字段。
2. 提供相关原文、表格或已读入的解析结果，并保留来源位置。
3. 说明输出要求：例如单位、表格列名，以及缺失信息如何标记。
4. 检查生成结果是否与原文一致，是否混淆不同样品或条件。

上传 PDF 之后，工具可能只提取文字，也可能处理图像、表格或部分页面，具体取决于产品。不要默认整个文件的所有内容都已进入上下文，尤其要核对图表、公式与扫描页。

这里只演示如何理解输入来源，不在本节展开 PDF 解析工具或布置额外文献作业。

## 九、从上下文接到 Harness

刚才的脚本已经做了两件模型外的事：读取本地文件、组织消息列表。模型只接收到程序提交的内容。

下一步，我们希望程序能围绕目标选择相关资料、协调模型提出的工具调用、执行操作，并把结果送回上下文。这些就进入下一节的 Harness 与 Agent 工作过程。

**课堂检查：**

1. 关闭系统提示词后，为什么仍然是聊天模式？
2. 聊天窗口里出现过一条记录，是否保证后续请求包含它？
3. 文件保存在电脑上，模型是否就能知道其中内容？
4. 已提供原文，是否足以保证模型回答正确？

参考回答：聊天模板和训练行为仍保留；需要检查实际请求或历史管理；需要读取并提供；信息充分与正确利用信息是不同问题。

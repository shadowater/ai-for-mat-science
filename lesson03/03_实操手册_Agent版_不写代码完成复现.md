# 第三课 · 实操手册（Agent 版）：你只动嘴，代码交给 Agent

> **和 02 的关系**：02 是"自己写代码"版，03 是"指挥 Agent 写代码"版。两条路做的是同一件事，任选一条即可。
>
> **工具**：以 Claude Code（VSCode 扩展）为例，Cursor、Codex 等 Agent 同理。
>
> **路径约定**：文中路径都以仓库根目录（ai-for-mat-science）为基准。
>
> **核心原则**：你负责说清楚要什么、检查结果对不对；Agent 负责读文件、写程序、跑命令、看报错、改程序。**Agent 会一本正经地编数字，每一步都要验收。**

## 0. 这一版怎么上课

| 环节 | 你做 | Agent 做 |
|---|---|---|
| 读论文 | 判断哪张表有用 | 把 PDF 转成文字、定位表格 |
| 提数据 | **人工抄一遍，作为标准答案** | 按约定格式批量提取 |
| 校验 | 抽查、判断是否合理 | 跑工具、查范围、做对比 |
| 建模 | 说清要求、判断指标是否可信 | 写程序、训练、画图 |
| 网页 | 描述页面要什么 | 写页面、启动、修报错 |

全程只需要反复做三个动作：

1. **先让它说计划**："先说你想怎么做，别动文件，等我确认。"
2. **要原始输出**："把完整运行结果贴出来，不要只给结论。"
3. **一次只改一处**："只修这个报错，别顺手改别的。"

一句话：

> **"不写代码" ≠ "不做判断"。** 你省下的是敲键盘，省不下的是审核。

## 2. 工具介绍：PDF 怎么读，SMILES 怎么验

**这一步在干什么**：先知道有哪些工具、各自擅长什么，再决定用哪个。Agent 能替你调用这些工具，但**选哪个、信不信，得你定**。

### 2.1 PDF 解析工具

| 工具 | 怎么用 | 擅长 | 注意 |
|---|---|---|---|
| **UniParser** | 网页上传 / 接口 | 中文友好；表格、公式、结构式保留较好 | 大文件要分段；图表编号要核对 |
| **MinerU** | 开源，可本地跑 | 版面分析强，公式转 LaTeX，适合论文 | 本地跑要显存；化学结构图仍需另外识别 |
| **Marker** | 开源 | 转出的 Markdown 干净、速度快 | 表格偶尔错位 |
| **GROBID** | 开源 | 学术 PDF 的章节、参考文献结构清楚 | 不处理化学结构 |
| **Agent 直接读** | 把 PDF 路径给它 | 页数少时最快，零配置 | 页数多容易漏，表格复杂会乱 |

网址见附录 B。

### 2.2 结构图转 SMILES（OCSR）

论文里的分子往往画成图，机器需要的是 SMILES 文字。**OCSR**（光学化学结构识别）就是干这个的。

| 工具 | 怎么用 | 说明 |
|---|---|---|
| **OCSR** | 网页 ocsr.dp.tech | 上传结构图，输出 SMILES，上手最快 |
| **MolScribe** | 开源 | 精度较好，需要本地部署 |
| **DECIMER** | 网页 / 开源 | 适合批量识别 |
| **OSRA** | 老牌开源工具 | 输出格式常需清理 |

> 结构图识别**一定会出错**，尤其是手绘、低分辨率、跨页的图。规则是：**识别结果必须和原文图对照检查**。

### 2.3 SMILES 校验工具

| 工具 | 能做什么 | 说明 |
|---|---|---|
| **RDKit**（让 Agent 调用） | 判断能否解析、规范化写法、补全端基、算描述符 | 化学信息学的通用标准，最可靠 |
| **PubChem** | 查已知化合物的规范 SMILES | 小分子好用，聚合物基本查不到 |
| **Cactus 结构解析服务** | 名称和结构互相转换 | 在线服务，偶尔不稳定 |
| **OCSR 交叉核对** | 把结构图重新识别一遍，和文字 SMILES 对比 | 两个结果不一致，就回原图看 |

### 2.4 怎么选

- 表格多、要保结构 → 先用 **UniParser 或 MinerU**，再交给 Agent；
- 中文论文 → **UniParser** 优先；
- 有显卡、想离线 → **MinerU**；
- 只有几页、表格简单 → **让 Agent 直接读**；
- 有结构图 → **OCSR / MolScribe / DECIMER** 识别，再人工对照；
- 校验 SMILES → **让 Agent 调 RDKit**，必要时用 OCSR 复核。

### 2.5 一个提醒

任何工具的输出都只是"草稿"。**数字和结构，最终以论文原图原表为准。**

## 5. 第 3 步：先约定"每条记录长什么样"

**这一步在干什么**：在让 Agent 提取之前，先把输出格式定死。否则它这次给你一张表、下次给你一段话，还没法逐格核对。

### 5.1 JSON 是什么

JSON 是一种记录数据的纯文本格式，核心就是"**字段名: 值**"，用大括号把一条记录包起来。比如：

```json
{
  "polymer_id": "PI-1",
  "tg_dsc_C": 262,
  "tg_dma_C": 271
}
```

读法：

- 大括号里是**一条记录**；
- 引号里的是**字段名**；
- 冒号后面是**值**；文字要加引号，数字不加；
- 字段之间用逗号隔开。

> **注意**：JSON 只是一种记录格式，不是程序。你不需要会写程序，只要能看懂"这个字段填的是什么"。

### 5.2 JSON Schema 是什么

**Schema 就是"填写说明"或者"表格模板"。** 它不记录数据，而是规定：

- 一条记录**必须有哪些字段**；
- 每个字段是**数字、文字，还是可以为空**；
- 有些字段只能从几个选项里挑（比如可信度只能填高、中、低）。

可以把 Schema 想成一张**空白表格的格式说明**，JSON 是**按这个格式填好的那一行**。

### 5.3 怎么写一份最小的 Schema

分五步：

1. **先列出你要的字段**（先别管格式）；
2. **给每个字段定类型**：数字、文字，还是可以为空；
3. **需要出处的字段，单独放一个小块**（表号、页码、原文）；
4. **标出哪些必须填**；
5. **能枚举的字段给出选项**（如可信度）。

按这五步，本课要的字段是：

| 字段 | 含义 | 类型 |
|---|---|---|
| polymer_id | 聚合物编号 | 文字 |
| smiles | 结构式，没有就空 | 文字或空 |
| tg_dsc_C | DSC 测的 Tg | 数字或空 |
| tg_dma_C | DMA 测的 Tg | 数字或空 |
| lambda_cutoff_nm | 截止波长 | 数字或空 |
| cte_ppm_per_K | 热膨胀系数 | 数字或空 |
| source | 出处：表号、页码、原文 | 一个小块 |
| notes | 备注：范围值、单位换算、冲突 | 文字 |
| confidence | 可信度 | 高 / 中 / 低 |

写成 Schema 就是：

```json
{
  "type": "object",
  "properties": {
    "polymer_id": {"type": "string"},
    "smiles": {"type": ["string", "null"]},
    "tg_dsc_C": {"type": ["number", "null"]},
    "tg_dma_C": {"type": ["number", "null"]},
    "lambda_cutoff_nm": {"type": ["number", "null"]},
    "cte_ppm_per_K": {"type": ["number", "null"]},
    "source": {
      "type": "object",
      "properties": {
        "table": {"type": "string"},
        "page": {"type": "integer"},
        "quote": {"type": "string"}
      },
      "required": ["table", "quote"]
    },
    "notes": {"type": "string"},
    "confidence": {"type": "string", "enum": ["high", "medium", "low"]}
  },
  "required": ["polymer_id", "source"]
}
```

逐句解释：

- **type: object** —— 一条记录是一个"对象"（也就是一个大括号）；
- **properties** —— 这条记录有哪些字段；
- **type: ["number", "null"]** —— 可以是数字，也可以是空；**没找到就填空，不许编**；
- **source 里的 required** —— 出处至少要有表号和原文，页码能填就填；
- **enum** —— 只能从 high、medium、low 里选一个。

> **写 Schema 的口诀**：先想"一条记录要有哪几列"，再想"每列是数字还是文字、能不能空"，最后加上"出处"和"备注"。

## 6. 第 4 步：校验，Agent 最容易出错的地方

**这一步在干什么**：提取出来的数据不能直接用，要过四道检查——**结构式能不能识别、端基补全没有、数值合不合理、结构有没有重复**。

### 6.1 四类校验

| 检查 | 规则 | 常见错误 |
|---|---|---|
| 结构式解析 | 必须能被 RDKit 识别 | 括号不配对、价态错误、复制时混入空格 |
| 端基补全 | 两端连接点换成氢，补全前后重原子数不变 | 直接把连接点删掉，等于删原子 |
| 数值范围 | Tg 0–500 °C；截止波长 200–600 nm；CTE −50–200 ppm/K | 小数点错、单位错 |
| 去重 | 用**规范化后的结构式**比对，不用原始字符串 | 同一结构不同写法被当成两条 |

### 6.2 推荐提示词 4

> 请写一个小工具，检查 lesson03/work/extracted_raw.json 里的四条数据，结果写成 lesson03/work/report.md。检查四件事：
>
> 一，每条结构式能不能被 RDKit 正确识别，不能的说明原因；
> 二，结构式两端的连接点是不是已经用氢补全，补全前后重原子数应该不变；
> 三，数值是否在合理范围：Tg 0–500 度，截止波长 200–600 纳米，CTE 负 50 到 200，越界的标出来；
> 四，和 lesson03/example/ref.c6ra00322b_extracted.csv 逐格对比，列出所有对不上的地方。
>
> 先告诉我你打算怎么做，等我说可以再动手。做完把完整运行结果贴给我，不要只说结论。

### 6.3 验收

- 四条结构式全部识别成功；
- 补全前后重原子数一致（示例论文里是 68、64、66、66）；
- 数值没有越界，Ref-PI 的截止波长被标成"缺失"而不是 0；
- 和参考文件的差异清单为空，或每条差异都有解释。

### 6.4 用 OCSR 做交叉核对

如果对某条结构式不放心：

1. 从论文里截下该聚合物的结构图；
2. 用 OCSR（ocsr.dp.tech）识别一次，得到另一个 SMILES；
3. 让 Agent 把两个 SMILES 都用 RDKit 规范化，再比较是否一致；
4. **不一致就回原图看**，不要二选一硬猜。

> 提醒：`ref.c6ra00322b_extracted.csv` 里的结构式带连接点，是**重复单元**，正好用来练习补全。

6. **每阶段确认一次**：没问题再进入下一步，出错能回退；
7. **小步修改**：报错一条一条修，不要让它"顺便重构"；
8. **听不懂就问**：让它用大白话解释每一步在做什么；

## 14. 常见坑（Agent 版）

| 现象 | 原因 | 处理 |
|---|---|---|
| 出现论文里没有的数字 | 模型幻觉 | 要求每条带原文出处，逐个核对 |
| 把 262–275 拆成几个数 | 把范围当列表 | 明确要求范围写进备注 |
| Tg 只提了一列 | 没区分 DSC 和 DMA | 约定两个字段 |
| 单位写成 cm⁻¹ | 把波长当波数 | 校验范围 200–600 纳米 |
| 结构式没补全就训练 | 直接把连接点删了 | 要求补全前后重原子数一致 |
| 测试集分数异常高 | 在全量数据上做筛选 | 检查是否用了测试集 |
| 网页预测值离谱 | 特征顺序或版本不一致 | 对比命令行和网页的结果 |
| 说"已完成"但没日志 | 没真跑 | 让它重跑并贴运行结果 |
| 改了原始数据 | 没加只读约束 | 检查工作区改动，必要时恢复 |

## 1. 任务介绍：为什么设计聚酰亚胺

### 1.1 应用背景（约 15 min）

- 柔性显示/柔性电子要求基板同时满足：
  - **光学**：高透明，430 nm 透过率 > 80%，近无色（OLED 显示要求）；
  - **热学**：Tg > 300 °C，能承受 TFT 沉积等高温工序；
  - **尺寸稳定性**：CTE 与金属电极匹配，避免热应力导致翘曲、分层。
- PI 是少数能同时逼近这三者的高分子，但"透明"和"耐热/低膨胀"天然矛盾：
  - 引入 −CF₃、−SO₂−、脂环等打断电荷转移（CT）相互作用 → 变透明；
  - 但链堆积变松 → Tg 下降、CTE 上升。
- 因此 PI 设计的本质是**多目标折中**，这正是机器学习能发挥价值的地方。

### 1.2 化学基础：PI 是怎么合成的（配图讲解）

**使用图片**：`example/Formation_of_polyimid.png`

讲解顺序：

1. **(A) 二酐 + 二胺**：二酐（图中为均苯四甲酸二酐 PMDA 型）与 H₂N–R–NH₂ 在溶液中开环加成；
2. **(B) 聚酰胺酸（PAA）**：生成含 −COOH / −CONH− 的线性中间体，可涂膜；
3. **(C) 热酰亚胺化**：升温脱水（−2 H₂O），形成五元酰亚胺环，得到 PI；
4. 图中 **R = 4,4′-二苯醚（ODA）**，说明" changing R 就是 changing 性能"。

课堂提问：
- 若把 R 中的 −O− 换成 −C(CF₃)₂−，Tg、CW、CTE 分别会怎么变？
- 为什么重复单元两端要"封端"才能变成可计算的分子？（引出 §4）

### 1.3 三个目标性质

| 性质 | 符号 | 单位 | 物理含义 | 测量方法（本课口径） |
|---|---|---|---|---|
| 玻璃化转变温度 | Tg | °C | 链段开始协同运动的温度 | **只用 DSC**（10 °C/min，N₂） |
| 截止波长 | CW / λ_cut-off | nm | UV-vis 透过率曲线切线与基线交点，反映颜色深浅 | UV-vis 200–800 nm |
| 热膨胀系数 | CTE | ppm/K | 单位温升的尺寸变化率 | TMA 50–250 °C |

> 教学要点：Tg 有 DSC / DMA / TMA 多种测法，DMA 通常比 DSC 高几度到几十度。**混用测法会引入系统误差**，论文因此只保留 DSC 数据——这是数据清洗的第一个真实案例。

### 1.4 论文做了什么

- 收集 **Tg 1674 条、CW 623 条、CTE 512 条**，来自 PolyInfo 与 2012–2024 年约 400 篇文献；
- 用 RDKit 计算 **210 个描述符**，方差筛选后保留 131 / 140 / 144 个；
- 比较 **RF、ET、GBR、XGB、LGBM、CATB、DNN** 七种算法；
- 最优模型：Tg 用 CATB（R²=0.865，RMSE=25.6 °C），CW 用 CATB（R²=0.874，RMSE=15.0 nm），CTE 用 RF（R²=0.855，RMSE=8.3 ppm/K）；
- 用 **SHAP** 找出关键描述符：`NumRotatableBonds`（Tg）、`BCUT2D_LOGPLOW`（CW）、`BCUT2D_CHGLO`（CTE）；
- 按 Tg ≥ 340 °C、CW ≤ 360 nm、CTE ≤ 50 ppm/K 筛选，合成 PI1–PI6 验证，并设计 **135 个新 PI**，用 SAscore 评估合成可及性。

## 3. 从 PDF 到数据集：解析—提取—校验

> 这是本课最能体现"Agent 进课堂"的一节。目标不是让学生手工抄表，而是建立一条**可审计**的流水线：每一步都能回答"这个数字从哪来"。

### 3.1 为什么需要这条流水线

- 论文自带的数据只有 1674/623/512 条，且截止 2024 年；要做新体系必须持续补数据；
- 一篇综述动辄几十张表、上百个结构式，手工提取既慢又容易错；
- LLM 能读 PDF，但**会幻觉**——所以必须"解析 → 结构化提取 → 规则校验 → 人工抽检"四步走。

### 3.2 第一步：PDF 解析（PDF → Markdown / JSON）

**工具选型**（课堂演示 2–3 个即可）：

| 工具 | 类型 | 优点 | 注意 |
|---|---|---|---|
| **UniParser** <https://uniparser.dp.tech/> | 在线/API | 中文友好，表格、公式、结构式保留较好 | 大文件分段；核对图表编号 |
| **MinerU** | 开源 | 版面分析强，公式转 LaTeX，可本地跑 | 显存要求；化学结构图需 OCR |
| **Marker** | 开源 | Markdown 干净，速度快 | 表格偶有错位 |
| **GROBID** | 开源 | 学术 PDF 结构化（章节/参考文献） | 不做化学结构 |
| **PyMuPDF (fitz)** | 代码库 | 纯文本兜底，稳定 | 丢失表格结构 |
| **OSRA / MolScribe / DECIMER / OCSR** | 专用 | 结构图 → SMILES | 手绘/低分辨率易错 |

**课堂演示**：用 `example/ref.c6ra00322b.pdf`（RSC 论文，11 页）跑一遍 UniParser，观察输出：

- 摘要、正文、参考文献 → 文本；
- Table 3（热性能）、Table 5（光学性能）→ HTML `<table>`；
- Scheme 1/2 的结构式 → 被转成一段段 SMILES 文本（这是"意外之喜"，但不保证每篇都有）；
- 上下标、希腊字母 → LaTeX 片段（`\(T_{\mathrm{g}}\)`），后续要清洗。

> **教学点**：解析工具的输出质量决定后面 80% 的工作量。先检查"表格是否完整、结构式是否丢失、数字有没有和单位粘连"，再决定是否换工具。

### 3.3 第二步：结构化提取（Markdown → 表）

**推荐方式：Agent + JSON Schema + 证据字段**

Schema 示例（直接用于提示词）：

```json
{
  "polymer_id": "PI-1",
  "smiles": "……",
  "tg_dsc_C": 262,
  "tg_dma_C": 271,
  "lambda_cutoff_nm": 322,
  "cte_ppm_per_K": 68,
  "source": {
    "file": "ref.c6ra00322b.pdf",
    "table": "Table 3",
    "page": 6,
    "quote": "PI-1 262 271 468 500 50 68"
  },
  "confidence": "high"
}
```

**三条硬规则**：

1. 每个数值必须带 `source.table/page/quote`，无证据不填；
2. 一个聚合物一条记录，不要把"范围值"（如 262–275）擅自拆成单值；
3. 单位不同的先换算再写，并在 `notes` 里记原值。

**备选方式**：规则/正则（适合格式统一的表）+ `pandas.read_html()`；Agent 负责"兜底"和"跨表关联"，规则负责"批量、可复现"。

### 3.4 第三步：校验（本课的核心训练）

#### （1）SMILES 校验

```python
from rdkit import Chem
mol = Chem.MolFromSmiles(smiles)      # None = 失败
Chem.SanitizeMol(mol)                 # 价态/芳香性检查
canon = Chem.MolToSmiles(mol)         # 规范化，用于去重
```

- 失败常见原因：括号不配对、芳香原子价态错误、`*` 位置非法、从 PDF 复制时混入空格/换行；
- **OCSR 交叉核对**：用 <https://ocsr.dp.tech/> 把论文里的结构图重新识别成 SMILES，与文本提取的 SMILES 比对；不一致就回看图。

#### （2）聚合物端基处理（重点）

论文的重复单元两端是"开口"的，常见三种写法：

| 写法 | 含义 | 处理 |
|---|---|---|
| `*c1ccc(...)...N(*)` | 两个 `*` 为连接点 | 统一替换为 `[H]` 封端 |
| `[*:1]...[*:2]` | 带原子映射的连接点 | 用正则/图方法替换，保留映射信息到备注 |
| `[H]...` / 无标记 | 已封端 | 检查两端是否都封端 |

**不能直接删 `*`**：`*` 是一个真实原子节点，删掉等于删原子；`N(*)` 删成 `N()` 会直接语法错误。正确做法：

```python
import re
from rdkit import Chem

def cap_wildcards(smi: str):
    mol = Chem.MolFromSmiles(smi)
    if mol is None:
        return None
    mol = Chem.ReplaceSubstructs(
        mol,
        Chem.MolFromSmarts("[#0]"),      # 只匹配 dummy 原子
        Chem.MolFromSmiles("[H]"),
        replaceAll=True,
    )[0]
    Chem.SanitizeMol(mol)
    return Chem.MolToSmiles(Chem.RemoveHs(mol))
```

校验前后要满足：

- 重原子数不变（封端只加 H）；
- 分子式只多 2 个 H；
- 规范 SMILES 可稳定复现。

#### （3）数值校验

| 检查 | 规则 | 处理 |
|---|---|---|
| 范围 | Tg 0–500 °C；CW 200–600 nm；CTE −50–200 ppm/K | 越界回查原文 |
| 单位 | ppm/°C ≡ ppm/K；nm 不要写成 cm⁻¹ | 统一后再入库 |
| 量级 | CW 305 vs 3050 明显异常 | 检查小数点/单位 |
| 交叉一致 | 摘要 vs 表格 vs 正文 | 不一致时以表格为准并记录 |

**真实案例（本课会现场演示）**：论文摘要写 Tg 的 MAE = 18.1 °C，Table 1 写 18.7 °C。同一篇文章内部就不一致——这正是"必须留痕、必须交叉核对"的理由。

#### （4）去重与合并

- 用规范 SMILES（canonical）去重，不要用原始字符串；
- 同一结构不同测法/不同文献的多条数据：保留全部但加 `method`、`source` 字段，训练时再按规则筛选；
- 合并新数据到主表时，按 `canonical_smiles` 左连接，禁止按行号硬拼。

### 5.2 七种算法一览

| 算法 | 一句话原理 | 关键超参数 |
|---|---|---|
| **RF** 随机森林 | Bagging + 随机特征，多棵树平均 | `n_estimators`, `max_depth`, `max_features`, `min_samples_*` |
| **ET** 极端随机树 | 分裂阈值也随机化，方差更小 | 同 RF |
| **GBR** 梯度提升 | 逐步拟合残差 | `n_estimators`, `learning_rate`, `max_depth` |
| **XGB** | 正则化梯度提升 + 二阶信息 | `eta`, `max_depth`, `subsample`, `colsample_bytree` |
| **LGBM** | 叶子优先生长，速度快 | `num_leaves`, `learning_rate`, `n_estimators` |
| **CATB** | 有序提升，对小数据/类别特征友好 | `iterations`, `depth`, `learning_rate` |
| **DNN** | 多层感知机，自动学非线性 | 隐藏层数/节点、激活、dropout、优化器、lr、batch、epochs |

### 5.5 评估指标（务必讲透）

| 指标 | 公式 | 含义 | 陷阱 |
|---|---|---|---|
| R² | \(1-\frac{\sum(y-\hat y)^2}{\sum(y-\bar y)^2}\) | 解释了多少方差，越接近 1 越好 | 对异常值敏感；复杂度增加可能虚高 |
| MAE | \(\frac1n\sum\lvert y-\hat y\rvert\) | 平均绝对误差，单位同 y | 对极端误差不敏感 |
| RMSE | \(\sqrt{\frac1n\sum(y-\hat y)^2}\) | 均方根误差，惩罚大误差 | 受异常值影响大 |
| R | Pearson 相关系数 | 线性相关强度 | 论文用 \(\sqrt{R^2}\) 代替 R，仅在 R²>0 时近似成立，课堂要说明 |
| CV | 10 折均值 ± 标准差 | 稳定性 | 折间方差大 = 模型不稳 |

**怎么读图**：

- 散点图（预测 vs 实验）越贴近 y=x 越好；
- 残差直方图应集中在 0 附近、近似对称；
- 训练集与测试集指标差距大 = 过拟合。

**论文为什么优先 RMSE/MAE**：R² 会被模型复杂度"虚抬"，而 RMSE/MAE 直接回答"预测值离真值多远"，对材料设计更有意义。

| C | 分子图（原子/键） | GCN/GAT | 最符合化学直觉 | 实现复杂、小数据易过拟合 |

### 6.2 1D CNN 结构（建议）

```
Input (2048, 1)
 → Conv1D(filters=64, kernel_size=5, padding="same", activation="relu")
 → BatchNormalization()
 → MaxPooling1D(pool_size=2)
 → Conv1D(filters=128, kernel_size=3, padding="same", activation="relu")
 → BatchNormalization()
 → MaxPooling1D(pool_size=2)
 → GlobalAveragePooling1D()
 → Dropout(0.3)
 → Dense(64, activation="relu")
 → Dense(1)                      # 回归输出
```

### 6.3 参数说明表（课堂重点）

| 参数 | 推荐值 | 作用 | 调参建议 |
|---|---|---|---|
| `input_dim` | 2048（Morgan r=2） | 指纹长度 | 与 `nBits` 一致；也可试 1024/4096 |
| `filters` | 64 → 128 | 每层卷积核数量 | 数据少时别超过 256 |
| `kernel_size` | 3 / 5 / 7 | 一次看多少个相邻位 | 指纹无顺序，3–5 足够；过大易过拟合 |
| `strides` | 1 | 滑动步长 | 一般保持 1，用池化降维 |
| `padding` | `"same"` | 保持长度 | 序列任务常用 |
| `activation` | ReLU | 非线性 | 可试 GELU |
| `BatchNormalization` | 开 | 稳定训练、加速收敛 | 小 batch 时慎用 |
| `pool_size` | 2 | 降采样 | 两层池化后 2048→512 |
| `Dropout` | 0.2–0.5 | 防过拟合 | 数据越少取值越大 |
| `Dense` 单元 | 64 | 特征压缩 | 最后 `Dense(1)` 线性输出 |
| `optimizer` | Adam | 自适应学习率 | 可换 AdamW |
| `learning_rate` | 1e-3 | 步长 | 不收敛降到 1e-4 |
| `loss` | MSE | 回归损失 | 异常值多可换 Huber |
| `batch_size` | 32 / 64 | 批大小 | 小数据用 32 |
| `epochs` | 200（上限） | 训练轮数 | 配合早停 |
| `EarlyStopping` | patience=20, restore_best_weights=True | 防过拟合 | 监控 `val_loss` |
| `ReduceLROnPlateau` | factor=0.5, patience=10 | 学习率衰减 | 监控 `val_loss` |
| `validation_split` | 0.2 | 验证集 | 从训练集里再切 |
| `random_seed` | 42 | 可复现 | 固定 numpy/tf/torch 种子 |

### 6.4 训练与评估流程

1. 用 RDKit 生成 Morgan 指纹（`radius=2, nBits=2048`），得到 `(n, 2048)` 的 0/1 矩阵；
2. 按 80/20 划分训练/测试；训练集再切 20% 做验证；
3. 训练 1D CNN，早停；
4. 与 CatBoost/RF 在同一划分上对比 R²、MAE、RMSE；
5. 画学习曲线（train/val loss）与 parity plot。

### 6.5 预期与讨论

- 小数据（500–1700 条）上，1D CNN **通常打不过** CatBoost/RF；
- 原因：指纹位是哈希映射，缺少真正的局部顺序；树模型对稀疏 0/1 特征更高效；
- 讨论题：如果换成 **GCN** 或 **预训练分子模型（MolFormer 等）**，结果会怎样？代价是什么？
- 结论：**没有免费午餐**——模型选择要匹配数据规模与表示方式。

## 7. 可解释性：SHAP

### 7.1 为什么需要

- 树模型/神经网络是黑箱，材料学家关心的是"改哪个结构能让 Tg 上去"；
- SHAP 把每个预测拆成"每个特征的贡献值"，既有全局重要性，也有单样本解释。

### 7.2 原理（点到为止）

- 基于 Shapley value：一个特征对预测的贡献 = 它在所有特征子集中的平均边际贡献；
- 满足可加性：\(\hat y = \text{base value} + \sum_i \phi_i\)；
- 对树模型用 `TreeExplainer`（精确、快）；对任意模型用 `KernelExplainer`（慢）；对神经网络可用 `DeepExplainer`。

### 7.3 三种图怎么读

| 图 | 横轴 | 颜色 | 回答的问题 |
|---|---|---|---|
| Bar plot | mean\|SHAP\| | — | 哪个特征最重要 |
| Summary plot | SHAP 值 | 特征值高低（红高蓝低） | 特征值大→预测升还是降 |
| Dependence plot | 特征值 | — | 关系是否线性/有转折 |
| Waterfall | 单样本 SHAP | — | 这一条为什么预测成这样 |

### 7.4 论文结论（课堂对照）

| 性质 | 最重要描述符 | 关系 | 化学解释 |
|---|---|---|---|
| Tg | `NumRotatableBonds` | 负相关 | 可旋转单键越多 → 链越柔 → Tg 越低 |
| CW | `BCUT2D_LOGPLOW` | 正相关 | logP 加权 Burden 特征值越大 → 共轭/疏水堆积越强 → 截止波长红移 |
| CTE | `BCUT2D_CHGLO` | 在约 −2.17 处转折 | 电荷加权 Burden 特征值影响链间作用与堆积 |

> 教学提醒：SHAP 是**相关性解释**，不是因果；特征间共线性会让贡献"分摊"；外推区间外的预测不可信。

### 7.5 复现方案

| 步骤 | 操作 | 产物 |
|---|---|---|
| 1 | `shap.TreeExplainer(model)` | explainer |
| 2 | `shap.summary_plot(shap_values, X)` | Figure 4a–c 复刻 |
| 3 | `shap.dependence_plot("NumRotatableBonds", ...)` | Figure 4e–g 复刻 |
| 4 | 对 PI-1 做 waterfall | 单样本解释图 |
| 5 | 写 3 条"结构设计建议" | 1 页报告 |

### 8.2 合成可及性：SAscore

- RDKit `sascorer` 计算 SAscore，越低越易合成；
- 经验阈值：< 6 表示易合成；论文中 135 个新 PI 全部 < 7，仅 6 个 > 6；
- 课堂讨论：为什么"预测性能最好"的分子不一定值得合成？

### 8.3 论文的验证

- 合成 PI1–PI6，实测 Tg/CW/CTE 与预测对比（Table 2），偏差多在几度/几 nm/几 ppm；
- 设计 135 个新 PI，筛出 12 个综合优候选（Figure 6）。

## 9. 做一个能用的 Demo

### 9.1 目标

输入一条聚合物 SMILES → 输出 Tg / CW / CTE 预测值 + 关键 SHAP 贡献 + 是否在适用域内。

### 9.2 技术选型

| 方案 | 难度 | 适用 |
|---|---|---|
| **Streamlit** | ★ | 最快，纯 Python，课堂首选 |
| Gradio | ★ | 适合快速分享 |
| FastAPI + 前端 | ★★ | 需要 API 分离 |
| 微信小程序 + 云函数 | ★★★ | 面向公众，需部署后端 |

### 9.3 架构

```
浏览器（输入 SMILES）
   │
Streamlit / API
   │
RDKit：解析 → 封端 → 210 描述符 → 选出模型所需列
   │
三个 .pkl 模型 → Tg / CW / CTE
   │
SHAP → top-5 贡献
   │
结果卡片 + 雷达图/柱状图
```

### 9.4 最小可用代码（Streamlit）

```python
import streamlit as st, joblib
import pandas as pd
from rdkit import Chem
from rdkit.Chem import Descriptors

st.title("PI 性能预测")
smi = st.text_input("输入重复单元 SMILES（两端用 [H] 封端）")

if smi:
    mol = Chem.MolFromSmiles(smi)
    if mol is None:
        st.error("SMILES 解析失败")
    else:
        row = {d[0]: d[1](mol) for d in Descriptors.descList}
        X = pd.DataFrame([row])
        tg = joblib.load("models/tg_catb.pkl").predict(X[FEATS_TG])[0]
        cw = joblib.load("models/cw_catb.pkl").predict(X[FEATS_CW])[0]
        cte = joblib.load("models/cte_rf.pkl").predict(X[FEATS_CTE])[0]
        st.metric("Tg / °C", f"{tg:.1f}")
        st.metric("CW / nm", f"{cw:.1f}")
        st.metric("CTE / ppm·K⁻¹", f"{cte:.1f}")
```

### 9.5 工程要点

- 模型只加载一次（`@st.cache_resource`）；
- 输入校验：SMILES 可解析、端基已封端、原子数在训练分布内；
- 适用域：用训练集描述符范围或 Morgan 相似度判断"外推"，给出警告；
- 不要把 RDKit 放到小程序前端（无法运行），用云函数/API；
- 结果页展示"预测值 ± 交叉验证 RMSE"作为不确定度提示。

### 9.6 复现方案

| 步骤 | 操作 | 产物 | 预计 |
|---|---|---|---|
| 1 | 保存 3 个模型 + 特征列 JSON | `models/` | 10 min |
| 2 | 写 `app.py` | 可运行页面 | 40 min |
| 3 | 本地 `streamlit run app.py` | 截图 | 10 min |
| 4 | 部署（内网/HF Spaces） | 链接 | 30 min |
| 5 | 用 PI1–PI6 验证页面输出 | 对照表 | 15 min |

## 附录 E：常见报错与修复

| 现象 | 原因 | 修复 |
|---|---|---|
